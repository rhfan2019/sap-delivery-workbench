# Gem FSD v2 移植实施与实测报告

日期：2026-10-06。结论：v2 试用功能已落地，旧版保留；**本次默认模型实测未达到五分钟完成目标，不能宣称移植成功复现 Gem 的速度或质量。**

## 一、实际完成的改造

采用两个核心文件，便于像维护一个 ABAP 报表一样集中阅读：

| 文件 | 职责 |
|---|---|
| `packages/agents/gem-fsd-v2.md` | 集中式提示词，移植 Gem 的需求到 FSD 九章流程 |
| `apps/api/src/gem-fsd-v2.mjs` | 集中式后端，包含上下文、一次生成、轻量校验、超时、保存、查询、取消 |

必要接线：新增 `GemFsdV2.vue` 试用面板，在现有设计页和 API 注册入口；新增数据库表 `app.gem_fsd_v2_run` 独立保存 v2 运行与文档。没有修改 `packages/contracts` 的旧版 FSD Schema，也没有拆出新的规划器、转换器或多 Agent 流程。

旧版提示词、执行器、说明书和历史继续使用原逻辑。v2 成果不自动写入旧版结构化编辑器，也不自动作为代码生成依据。本轮定位是独立的 FSD 试用版本，不包含生产审批、Word 导出或旧版章节编辑能力。

## 二、v2 的执行方式

1. 仅读取当前开发项基本信息及本轮业务补充；不读取旧版对话、附件或其他开发项历史。
2. 使用当前组织默认模型，复用现有凭据和流式传输程序。
3. 一轮只调用一次模型，直接输出 Markdown FSD；不单独生成任务规划、不生成大型 FSD JSON、不自动修复或续写。
4. 真正阻塞的业务问题用最多三题的小型澄清 JSON 返回；回答后显式发起下一轮，保留历轮问题与回答的对应关系。
5. 本地校验文档结束标记、九章顺序、最低内容量及禁止 ABAP 代码围栏。接受“第1章：”和“1.”等等价编号。**这不是业务质量校验，也不是 SAP 字典验证。**
6. 完整文档与终态在同一次数据库更新中保存，记录内容哈希。未完整输出不得标成保存成功。
7. 模型执行硬上限 360 秒；停止时中止上游请求，保留部分正文和日志。没有自动重试。

不调用 abap-adt MCP，不要求手工 DDIC 注入。SAP 对象、字段和接口只能作为待核实候选；提示词明确禁止声称已经读取系统或获得业务签认。

## 六、如何使用与处理失败

进入开发项的设计页，点击顶部 **Gem FSD v2（试用）**。填写业务补充后发起独立运行；旧版仍可从“返回旧版”进入。

- 生成中：显示耗时和字符数，可主动停止；刷新后从历史运行恢复。
- 待回答：显示问题及影响，填写回答后继续。
- 已保存：可查看 Markdown 并下载，保留内容哈希。
- 失败/超时：显示原因，下载完整日志查看部分输出；修订输入后手动新建运行。禁止将半成品标成完整说明书。
- 网络结果未知：保留请求编号，以“恢复本次请求”确认结果，重复提交同一请求不会重复调用模型。
- 进程中断：租约失效后标记中断，保留日志，不自动重新生成。断点续跑恢复检查点和已完成结果，不代表接着供应商未完成的文本自动续写。

日志包含业务输入与模型输出，下载按钮已经明示；模型凭据不进入日志。

## 七、命令程序与后续建议

执行器、分析器和记录器位于独立 `tools/fsd-batch` 目录；前端只是使用同一后端的交互入口。

```powershell
$env:FSD_COOKIE_FILE = '<已登录会话 cookie 文件路径>'
node tools/fsd-batch/gem-v2-pilot.mjs DEV-0007
node tools/fsd-batch/analyze-gem-v2.mjs DEV-0007
```

执行器持久化复制请求编号与运行编号，重新运行恢复同一案例，不隐式创建第二次模型调用；DEV-0002 只有 DEV-0007 完整保存后才允许执行。若要启动新的对照批次，应另建批次检查点，不删除原始证据。

建议下一步优先核实当前供应商是否支持降低/关闭推理，以及 Gem 实测所用模型与模式，再用冻结的同一输入做一次有上限的对照。**本轮没有擅自切换默认模型，没有添加未经供应商确认的推理参数，也没有扩大战时或继续反复试跑。** 在对照证明有效前，不推荐继续压缩业务关键内容、拆成更多模型调用或放宽完整性校验来制造“成功”。
