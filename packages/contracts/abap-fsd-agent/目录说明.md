# abap-fsd-agent契约

唯一机器契约维护入口。旧artifacts/fs-workspace/fsd-rice-contracts-v1是历史副本，不继续同步。

| 路径 | 职责 | 接入状态 |
|---|---|---|
| runtime.schema.json | 多轮消息与运行目标请求 | 现行API校验 |
| types.ts | 页面共享消息、画像及回执类型 | 已使用 |
| sse.mjs及声明 | SSE增量解析 | 已使用 |
| fsd/v1/r、i、c、e.schema.json | FSD四类内容，公共字段及类型contract | 源码契约，生成API尚未启用 |
| fsd/v1/review-envelope.schema.json | 独立服务端顾问确认记录 | 确认API尚未启用 |
| fsd/v1/validate.mjs | 结构、ID、引用、方向、确认快照/版本/传入哈希一致性 | 纯校验能力，尚未接入保存或确认API |
| fsd/v1/*.example.json | 最小结构样例 | 合成格式示例，不能作为可交付FSD |

## 本次兼容更新

四类systemContext.discoveryStatus支持partial，与真实系统画像有限识别一致；schemaVersion仍为1.0.0，既有字段未移除。规则包独立升级到1.1.0，不能把规则版本当规格数据版本。

问题status=accepted仍未解决；unresolvedIssueIds包含open与accepted，仅resolved移除，且accepted/resolved都须有处置说明。确认中acknowledgedIssueIds必须等于当前未解决集合。

## 纯校验边界

validateSpecContract(spec)返回valid、errors、qualityIssues及assurance。errors用于结构/引用不合法；没有测试覆盖或预期笼统作为qualityIssues，不因内容问题硬锁顾问完成。未来服务端必须将这些内容发现纳入问题快照，再让顾问知情确认。

validateReviewContract(spec,envelope,{contentSha256})要求输入哈希来自真实已保存版本，并核对版本和问题集合。它不计算数据库版本、不鉴权、不证明人类点击或证据真实，不应直接作为确认API放行器。

未来生成/确认服务还必须验证：证据是否实际保存、系统/对象/主张是否匹配、actor来自会话、confirmedAt来自服务端、consultant_confirmed有真实决定记录、产物保存成功及并发版本锁。本次不提前实现S05/S06/S13接口。

运行画像的abapRelease映射到FSD的abapVersion；discoveryStatus=partial说明有限发现，不能推断市场版本或部署模式。trusted字段不得由模型直接签发。
