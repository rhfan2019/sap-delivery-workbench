# 通用章节与来源映射

用途：确定性渲染合同，不作为每轮对话提示。输入为完整且保存成功的 FSD JSON。JSON 是唯一事实源，渲染不得增加算法、修改问题状态或编造用户确认。

采用四章骨架：1 开发需求部分、2 功能规范、3 业务逻辑、4 开发测试数据。固定保留三级标题“2.1 权限设计”，标题与下一标题之间只有空白；不得添加权限表、说明、待补充文字或占位。

| 文档区域                 | JSON 来源                                                              | 处理规则                                                                                 |
| ------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 文档信息                 | title/revision/riceType/systemContext                                  | 中文开发类型；真实平台信息及待确认状态；草稿与未执行 SAP 测试声明                        |
| 1.1 开发概览             | purpose/consultantDetails/contract                                     | 运行类型、使用者、输出方式；可选表达缺失显示未提供，不据示例猜测                         |
| 1.2 业务需求描述         | purpose/scope/requirements                                             | 需求和验收口径表；完整范围及排除项                                                       |
| 2.1 权限设计             | 无                                                                     | 正文严格为空                                                                             |
| 2 功能规范其余内容       | fields/对应类型contract                                                | R 展示选择及输出字段表；I/C/E 展示输入输出合同，不强套选择屏幕或 ALV                     |
| 3.1 业务处理步骤         | rules                                                                  | 按业务步骤编号，保持建议/待确认/可信确认状态；只渲染既有处理规则                         |
| 3.2 取数、计算与处理边界 | contract                                                               | 引用解析为业务含义，SAP 对象保持真实核验状态                                             |
| 4 开发测试数据           | tests                                                                  | 场景、数据及前置、预期、方法表；不声称实测                                               |
| 附录                     | 所有稳定引用/完整字段/systemContext/sources/sapObjects/evidence/issues | 保留规格、需求、规则、字段、测试、来源、问题的内部标识及关联；完整技术映射与全部遗留问题 |

正文使用业务名称和中文状态，不暴露协议键或内部 ID。关键未知仍在对应决定旁以问题描述显示；附录保留原稳定 ID，便于独立下载后的追溯。accepted 表示已知悉，仍未解决。

文字中的 HTML、表格分隔符和换行在渲染时处理，不运行模型输出的 HTML；用户文本不能插入额外标题或表格列。标题层次由确定性渲染生成，目录由前端从同一正文建立，不单独让模型生成目录。

兼容：旧 JSON 无须新字段即可渲染，缺少顾问表达不得用采购申请点检例子填充。顾问表达字段均为新增可选字段，不改变已有必填项、contractVersion 或引用规则。
