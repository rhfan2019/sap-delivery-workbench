# 报表功能说明书渲染合同

输入：通过 r.schema.json 校验的 R 规格。事实来自同一 JSON，由 consultant-renderer.mjs 确定性渲染；renderMarkdown/validateDraft 调用接口不变。

## 1 开发需求部分

1.1 开发概览提供项目/内容表：需求概述、运行类型、使用者、输出方式、交易量与响应目标。可选 consultantDetails 的 executionMode、users、outputMode 均使用 decision；缺失不猜测。

1.2 业务需求描述来自 purpose、scope、requirements，需求/验收表使用业务编号而非内部 REQ 标识。稳定需求与来源引用进入附录。

## 2 功能规范

2.1 权限设计只有标题，正文严格为空。

2.2 选择屏幕设计及其布局：consultantDetails.selectionLayout 说明布局，contract.selectionFieldIds 决定顺序，引用 fields 的唯一字段合同。选择字段表列：字段名称、输入方式、参考来源、必填/可选、业务说明、默认值。

2.3 选择屏幕检查确认：字段格式/校验规则表和空结果/异常处理。不得凭表格补造组合校验。

2.4 输出布局及样式：consultantDetails.outputLayout、contract.resultGrain/displayAndDrilldown。输出字段表列：字段/列标题、来源或计算、类型及长度、显示与编辑要求。contract.outputFieldIds 决定顺序。可选字段 businessLabel 使用顾问业务名称，inputStyle/displayRule 表达输入方式及显示编辑要求，后二者为 decision。缺少表达显示未提供，不自动推断可编辑。

字段来源若无已核验对象支撑，则显式标为候选映射待核验。内部 FIELD 标识、原字段名、方向、基数、来源目标、格式、默认、校验、映射、单位币种、SAP 对象引用完整保留于附录。

## 3 业务逻辑

3.1 按 rules 的既有顺序列出处理步骤、说明和决定；保留 proposed/open 的中文状态。问题 ID 在正文解析为问题说明，在附录保留稳定引用。

3.2 展示剩余 contract 的业务口径：报表目的、数据来源、计算规则、基准日、汇总、单位币种、对账。选择与输出引用已由字段表消费；颗粒度、显示、异常、容量已在对应章节消费。每个 contract 字段都有可读落点。

## 4 开发测试数据

按 tests 列出序号、场景、数据/前置条件、预期结果、验证方法。不假装建立了目标 SAP 数据或已完成业务验收。测试与需求/规则引用进入同版本附录。

## 验收

四章和选择/输出/测试表可阅读；2.1 正文为空；R/I/C/E 示例能校验和渲染；关键未知可见；正文不泄露内部标识或协议枚举；独立附录可追溯。模板仅复用结构，不把采购点检字段、审批或保存流程写入其他需求。
