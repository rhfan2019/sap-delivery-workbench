# 任务：形成设计任务计划

根据当前需求、回答、已有规格与系统信息，识别本次必须解决的设计问题。计划围绕业务依赖，不按模板章节机械分解。简单任务保持短计划；最多 8 项。

每项任务说明输入依赖、完成标准、相关实体与是否需要对象核验。已明确的信息不重新提问。计划不能宣告执行成功或批准阶段。返回唯一 JSON：

{"tasks":[{"id":"T1","goal":"确定每行含义","dependsOn":[],"doneWhen":"结果颗粒度、唯一键及重复处理明确","entityIds":[],"needsEvidence":false}],"scenario":{"editable":false,"objectFeedback":false}}

scenario 按真实业务动作判断。批量读取不等于可编辑；逐对象执行结果或重试才需要 objectFeedback。当前明确取消写操作时更新特征，不受历史示例污染。
