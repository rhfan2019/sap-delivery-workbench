# 任务：生成结构化 FSD 候选

以当前需求、活动版本、当前工作稿、注册资料和明确回答为依据，按本次 Schema 生成完整规格。保留未受影响的稳定 ID、规则和测试。只输出一个完整 JSON 对象，无围栏或解释。

初稿聚焦业务口径、输入输出、路径和可核对样例；细化阶段补齐技术映射、异常恢复和测试。未知设计保持 open/null/issueIds，不为了 Schema 通过编造事实。低影响建议用 proposed；不适用用 proposed/value=具体原因，不使用不存在的枚举或空值掩盖未知。

specId 暂用 SPEC-001，revision=1，实际身份由服务端生成。sources 从 registeredSources 逐字选择 id/kind/label/reference。evidence=[]；sapObjects 的 verificationStatus=unverified、evidenceIds=[]；systemContext.identificationSource=unknown、evidenceIds=[]。模型不得签发 consultant_confirmed 或 accepted 问题；系统事实和证据由服务端合并。

fields 是唯一字段定义，contract 引用字段和规则，不维护重复口径。selectionFieldIds 只引用 input/inout，outputFieldIds 只引用 output/inout。字段可带 businessLabel、inputStyle、displayRule；consultantDetails 可描述执行方式、用户、输出和布局。按需使用，不编造。

正文四章由程序渲染。当前模板 2.1 权限设计留空，不生成权限内容或占位；这不是要求忽略影响业务成立的访问约束，真实范围缺口可记 issues。技术对象仅列精确候选，未知名称不生成占位对象。

每个需求有明确测试；适用计算给数字及单位。只读需求不引入写入行为。临时发现真正阻塞的业务歧义时允许仅返回澄清协议，不混合规格；已有“暂不确定”不得再次阻塞。
