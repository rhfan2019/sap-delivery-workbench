# 可编辑批处理与并发

规则编号：BP-001。触发：可编辑列表、选中保存、批量业务动作；只读列表不加载。输入：编辑字段、稳定业务键、执行集合、事务组和候选接口。

### 6.1 可编辑批处理：变更、并发与提交

1. 查询时按稳定业务键保存原值与适用的版本信息，编辑值独立保存。最后一个单元格直接点击保存也必须进入校验；改回原值清除变更标记。
2. 明确执行集合：全部改动行或选中且改动行；解释零选、选中未改、已改未选及隐藏行。排序和筛选不改变业务键。
3. 按业务事务组确定锁范围及稳定加锁顺序。在保护范围内重读对象、状态与必要关联集合，比较版本及相关值，防止陈旧输入覆盖新状态。
4. 时间戳仅在确实存在、精度充分且覆盖相关变化时可用。没有可靠版本字段时，采用明确的锁内快照比较等替代方案；不得跨系统硬编码某案例字段。
5. 冲突保留编辑内容供对照，提示重新载入与重做修改；不能把数据库新版本号替换旧基线后直接提交旧输入。
6. 成功后回读实际值并更新基线；失败保留该组原值和编辑。回读失败标记结果待核对，不能沿用旧版本再提交。
7. 明确每个提交点、失败停止范围与补偿条件。前一步已提交、后一步失败，应显示部分完成，不能宣称全部回滚。
8. 结果未知先核对，成功组不重做；重试失败组仍需重新核对状态。只释放本次持有的锁，清理失败不能覆盖原始错误。
9. 刷新、重新查询、退出前保护未保存输入。取消或刷新失败保留编辑；部分保存不能覆盖其他未处理行。

## 写入与验收位置

将编辑生命周期、集合、锁内比较、每个提交点和失败结果作为rules，字段入fields；R的displayAndDrilldown说明交互，emptyAndExceptionBehavior说明恢复入口；具体约束不靠一个通用decision替代，需引用规则。tests覆盖最后单元格保存、改后改回、编辑未选、排序后保存、同单多行、时间戳缺失/精度、关联状态变化、锁冲突、提交点失败和刷新保护。

必须包含连续场景：编辑→他人修改→冲突→保留输入→重载→重做→保存；A组成功B组失败→只重试B；结果不明→核对实际状态再决定动作。不得复用成功组、不得承诺已提交业务可数据库回滚。

反例：将某系统EBAN-LASTCHANGEDATETIME字段及类型硬编码到所有版本。需验证字段存在、更新粒度及覆盖范围，不能单凭时间戳相等认定所有相关状态未变。
