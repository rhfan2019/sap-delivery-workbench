# 报表功能规则

规则编号：TYPE-R。适用：主类型R已选定或顾问要求分析该类型；混合类型先明确是否拆分，不以标题替换代替类型设计。

### 5.1 R：报表

必须覆盖：业务目的；选择条件的必输/默认/范围与组合校验；每行含义；完整字段及来源/公式；关联与去重；当前状态或基准日；币种、单位、符号、舍入；空结果；显示、排序、小计、导出、下钻；适用的操作；数据量及响应目标；对账方式。

不同币种/单位不能直接相加；需要换算时明确汇率/换算来源、日期、精度及缺失处理。复杂关联必须检查一对多导致重复金额的问题，不能仅因字段能Join就判定业务关系成立。历史报表不能用当前状态冒充基准日状态。

只读报表不强加保存、版本时间戳和编辑保护。带编辑或批处理动作时，额外加载第六章的实践规则。

验收至少包含：空数据、边界筛选、重复关联、部分执行/冲销（适用时）、单位币种差异、基准日前后变化，以及一组明确数字对账。不同开发者按规则应得到相同颗粒度和数值。

## 重要业务分歧的判断

结果按订单行还是收货行？历史时点还是当前状态？金额不同币种如何汇总？全量查询是否会改变需求范围或带来不可接受的业务影响？
能由资料、已确认规则和工具解决的先自行解决；确实未知则open+issue，不编造默认批准。专业建议写明适用条件，顾问可纠正。

## 输出合同

使用r.schema.json；contract必须完整覆盖：reportPurpose、resultGrain、selectionFieldIds、outputFieldIds、dataSources、calculationRuleIds、historicalCutoffRule、aggregationRule、currencyUnitRule、displayAndDrilldown、emptyAndExceptionBehavior、volumeAndResponseTarget、reconciliationMethod。

字段含义、方向、基数、来源目标路径、精度、默认、校验、映射、单位币种在fields定义。具体处理路径放rules，每条关联requirements；数字或状态例子落tests的input/preconditions/expectedResult。对象未核验进入sapObjects并关联issues，不以工具建议替代证据。

## 数字或状态例子

订单10件，净收货6件，若顾问确认“订单行未收数量”口径则结果4件；若之后冲销2件，净收货4件、结果6件。该算式仅用于这一已说明口径，不通用于暂估金额、寄售或关闭状态。

## 审查及反例

每个必要主题必须有本项目明确规则或带问题的未知表达，不能只写“考虑幂等/注意事务/做好性能”。测试必须能核对对象、数值或状态；不得把例子当真实系统运行记录。未涉及的标准动作不强行加入。关键定义变更后同步修订相关测试及引用。

普通布局、字段顺序、清楚的空结果提示可采用proposed建议继续；不将所有报表强制套用采购申请点检场景。不同单位分别输出，KG与EA不得合计；换算规则没有依据时不编造。选择字段和输出字段提供业务名称及完整表格表达，技术名称保持候选身份，权限设计正文留空。
