# 转换迁移功能规则

规则编号：TYPE-C。适用：主类型C已选定或顾问要求分析该类型；混合类型先明确是否拆分，不以标题替换代替类型设计。

### 5.3 C：转换/迁移

必须覆盖：业务对象与源目标；迁移范围与筛选；字段映射、清洗、默认和编码转换；主从依赖和装载顺序；装载方式候选；模拟；批次、检查点；拒绝及修复；重跑去重；数量、金额和关系对账/容差；切换窗口；恢复或补偿；业务完成口径。

每条源记录需能追踪到目标、拒绝或跳过原因。对账按同一统计口径定义源总量与各互斥结果集合，不能把重复跳过同时算成新成功。先完成主数据再处理依赖记录；转换失败不能用空值静默代替。

模拟不能产生业务过账；如某接口不能保证无副作用，需要明确限制并改用校验方案。不可逆过账不能承诺数据库回滚，恢复可以是业务冲销或补偿，并说明适用条件。无金额的对象说明金额对账不适用及原因。

验收至少包含：缺依赖、非法编码、重复源键、部分失败、修复后只重跑失败集合、断点恢复、容差内外差异及关系缺失。Agent不实际执行迁移。

## 必须澄清的业务分歧

迁移范围是否含历史关闭项？重复源记录如何裁决？允许怎样的对账容差？业务冲销还是补偿恢复？
能由资料、已确认规则和工具解决的先自行解决；确实未知则open+issue，不编造默认批准。专业建议写明适用条件，顾问可纠正。

## 输出合同

使用c.schema.json；contract必须完整覆盖：businessObjects、sourceSystem、targetSystem、migrationScope、loadMechanism、mappingRuleIds、cleansingAndDefaults、dependencyAndLoadOrder、simulation、batchCheckpoint、rejectionAndRepair、rerunDeduplication、reconciliation、cutoverWindow、recoveryOrCompensation、completionCriteria。

字段含义、方向、基数、来源目标路径、精度、默认、校验、映射、单位币种在fields定义。具体处理路径放rules，每条关联requirements；数字或状态例子落tests的input/preconditions/expectedResult。对象未核验进入sapObjects并关联issues，不以工具建议替代证据。

## 数字或状态例子

100条源记录按互斥集合统计：成功90、拒绝8、重复跳过2，合计100；修复8条后重跑只处理这8条，不能再次写入已成功90条。重复2条的业务处置需明确，不假装新成功。

## 审查及反例

每个必要主题必须有本项目明确规则或带问题的未知表达，不能只写“考虑幂等/注意事务/做好性能”。测试必须能核对对象、数值或状态；不得把例子当真实系统运行记录。未涉及的标准动作不强行加入。关键定义变更后同步修订相关测试及引用。
