# 接口功能规则

规则编号：TYPE-I。适用：主类型I已选定或顾问要求分析该类型；混合类型先明确是否拆分，不以标题替换代替类型设计。

### 5.2 I：接口

必须覆盖：发送接收方与方向；触发；同步/异步；消息版本、层级、基数、字段必输/格式/精度；映射及业务校验；技术接收与业务成功；提交边界；幂等；顺序；超时、部分失败、重试、重放及对账；峰值与时延目标。

幂等规则必须写清键的组成、唯一范围、同键同内容和同键不同内容的结果、重复窗口及结果查询方式。HTTP成功不自动等于SAP业务成功。超时后先判断结果是否未知，不能直接重发产生重复业务对象。批消息明确整批原子还是逐对象结果。

如依赖BAPI/FM，功能相关输入、输出、错误与提交语义必须明确；不要求写完整调用代码。接口字段使用消息路径，不能只列扁平字段名而丢失抬头/行项目归属。

验收至少包含：正常消息、缺必输、同键重复、同键内容变化、乱序、超时后结果未知、部分失败和重处理后对账。以上是验收设计，未联调时不能写“联调通过”。

## 必须澄清的业务分歧

业务成功在接收、过账还是回执时成立？同键不同内容拒绝还是变更？超时后如何查询原结果？
能由资料、已确认规则和工具解决的先自行解决；确实未知则open+issue，不编造默认批准。专业建议写明适用条件，顾问可纠正。

## 输出合同

使用i.schema.json；contract必须完整覆盖：direction、sender、receiver、interaction、trigger、protocolAndFormat、contractVersion、messageStructure、mappingRuleIds、successDefinition、transactionBoundary、idempotency、ordering、timeoutRetry、partialFailureRecovery、errorContract、monitoringAndReconciliation、volumeAndLatencyTarget。

字段含义、方向、基数、来源目标路径、精度、默认、校验、映射、单位币种在fields定义。具体处理路径放rules，每条关联requirements；数字或状态例子落tests的input/preconditions/expectedResult。对象未核验进入sapObjects并关联issues，不以工具建议替代证据。

## 数字或状态例子

请求K-01创建对象成功后回执丢失，重试同键同内容返回已有结果而不重复创建；同键内容变更应按明确契约拒绝或走变更流程。不能把超时直接当作创建失败。

## 审查及反例

每个必要主题必须有本项目明确规则或带问题的未知表达，不能只写“考虑幂等/注意事务/做好性能”。测试必须能核对对象、数值或状态；不得把例子当真实系统运行记录。未涉及的标准动作不强行加入。关键定义变更后同步修订相关测试及引用。
