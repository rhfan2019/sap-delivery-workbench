# 四类案例与预期问题

全部为合成验收输入，不作为系统证据。每个案例检查类型、必要提问、rules/fields/tests落点及问题保留。

| 类型 | 输入                                 | 必须说明/提问                                        | 反例                               |
| ---- | ------------------------------------ | ---------------------------------------------------- | ---------------------------------- |
| R    | 按订单行展示未收数量，允许退货/冲销  | 颗粒度、截止日、关闭项、单位、净数量样例及对账       | 关联收货多行导致订单数量重复汇总   |
| I    | 外部系统发采购创建消息，支持超时重试 | 消息键、成功定义、同键异内容、未知结果查询、部分失败 | HTTP200或接收回执直接算SAP创建成功 |
| C    | 迁移100条主数据，90成功8拒绝2重复    | 源记录去向、主从顺序、修复8条重跑、数量关系对账      | 重跑100条产生重复或称100条均成功   |
| E    | 指定工厂保存单据时校验数量           | 触发过滤、错误阻止行为、重入、宿主事务和标准回归     | 增强中擅自COMMIT、凭名称宣称适用   |

共同变体：未选择系统→询问SAP后端版本后继续业务；对象不可读→问题；顾问接受未核验问题→accepted仍遗留；改变版本→旧确认不能复用；只回答局部问题→不完成全文。

现有r/i/c/e.example.json仍为结构示例，不能用于业务评分。未来模型验收按这些场景独立生成并记录供应商、规则版本、实际Payload与输出，不把手工fixture当真实生成。
