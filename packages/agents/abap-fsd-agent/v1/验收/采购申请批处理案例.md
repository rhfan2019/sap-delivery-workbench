# 采购申请批处理案例

### 6.3 采购申请场景：规则包的首个业务验收案例

案例输入：采购申请列表允许修改数量和采购组、批量审批、按供应商/工厂创建采购订单、逐行显示结果并重试、支持模拟。

需要明确的业务选择：保存与审批是否串行必选；批量审批采用何种实际审批机制；供应商确定方式；除供应商和工厂外，采购组织、公司代码、币种等差异是否允许同单；失败时停止当前组还是后续全部；模拟覆盖哪些校验。

Agent不得默认“供应商+工厂”已经是充分的PO分组键，不得默认经典释放适用于全部版本，也不能把“审批成功”与“订单已创建”合成一个成功状态。对象及接口名称由实际核验支持。

连续验收：编辑→他人修改→冲突拒绝→保留输入→重新载入→重做修改→保存；A组成功B组失败→只重试B；修改已提交但审批失败→显示部分完成；PO创建超时结果未知→核对后再决定重试；模拟→无业务过账。

本节是设计验收案例，不表示已编写或运行SAP业务程序。现有采购申请复测仅证明对话供应商调用修复，不能替代此业务验收。

合成输入，不携带客户数据。建议R并加载BP-001/BP-002。预期提出分单、审批机制和动作依赖问题；技术名称保持候选。必须落实到规则和测试，不仅回复“需要考虑”。

失败判据：供应商/工厂被当成充分分组键；未核验就固定经典释放API；模拟产生真实单据；超时自动重复创建PO；成功组重做；先保存后审批失败被描述为全部回滚。

静态案例通过只代表规则覆盖，真实模型与SAP核验分别验收。
