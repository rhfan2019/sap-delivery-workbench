# 助手页起始页、输入框与成果访问设计

版本：0.1（待确认）。日期：2026-10-18。适用范围：`apps/web/src/features/agent-workbench`（设计助手 `abap-fsd-agent` 与开发助手 `abap-dev-agent` 共用）、`features/delivery` 的开发清单与开发项抽屉，以及对应后端路由。

本文来自 2026-10-18 用户对设计助手起始页（00030 全厂缺料分析）的审查，以及随后的头脑风暴。第 1 节列出问题，第 2 节记录用户已经做出的决策，第 3 至 6 节是设计方案，第 7 节是分期，第 8 节是验证要求。它与 [对话体验设计指引](agent-conversation-ux.md) 互补：那份文档管运行过程和右侧面板，本文管起始页、输入框、资料引用和权限入口。界面取值以 [DESIGN.md](DESIGN.md) 为准。

## 1. 审查发现

| #   | 问题                                               | 现状与原因                                                                                                                         |
| --- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 标题“今天要梳理哪个需求？”有歧义                   | 写死的通用文案（`AgentWorkbench.vue`）。用户是从某个具体开发项进来的，目的已经确定。                                               |
| 2   | 占位文字“描述需求，或继续追问…”多余                | 写在共用的 `ChatComposer.vue` 里。                                                                                                 |
| 3   | SAP 系统和模型的字号不一致                         | SAP 系统用原生 `<select>`，模型用 `Button`，浏览器对原生控件的渲染不同。                                                           |
| 4   | “梳理需求与待确认问题 / 直接起草 FSD 初稿”意义不明 | 两个按钮只是往输入框里填一句话。业务功能点通常维护得不规范，撑不起一份 FSD。真正的需求来源是顾问上传的附件、手工输入的文字和截图。 |
| 5   | 没有使用权限的人也能进助手页                       | 后端用 `:view` 放行页面读取，用 `:run` 控制编辑；清单行内和抽屉里的“设计/开发”按钮都不检查权限。抽屉里也看不到助手的成果。         |
| 6   | 模型看起来能选，实际不能选                         | 选择器只显示组织默认模型，却带着下拉箭头。后端 `resolveAgentModel` 只取组织默认模型。                                              |
| 7   | 底部信息过多                                       | 附件按钮、“Enter 发送 · Shift + Enter 换行”、SAP 系统、模型挤在同一行，提示文字一直显示。                                          |
| 8   | 主要的输入方式不明显                               | 拖拽和粘贴截图其实已经支持，但界面上只有一个“+”。                                                                                  |
| 9   | 助手不了解开发项资料                               | 会话事实里只有编号和名称（`abap-fsd-agent/context.mjs`），业务功能点和开发项附件都不交给助手，用户只能重新上传。                   |
| 10  | “新对话”出现两次                                   | 对话切换器的标题和右上角的“+ 新对话”按钮同名。                                                                                     |
| 11  | 成果面板按钮常驻                                   | 还没有成果时也能打开，打开后是空的。                                                                                               |
| 12  | 不支持的类型仍显示“开发”标签                       | 助手页顶部总是显示两个标签；清单和抽屉里是“即将推出”，行为不一致。                                                                 |
| 13  | 前后端的负责人口径不同                             | 清单按“创建人 + 所有阶段负责人”判断“仅本人”，后端按本阶段负责人（没有时用创建人）判断。入口按权限显示后，两边必须一致。            |

## 2. 决策记录（用户 2026-10-18 确认）

1. **权限**：只有“查看”权限、没有“使用”权限的人，不能进入助手页。他们只能在开发项抽屉里查看成果（FSD、开发方案与代码），看不到对话过程。
2. **资料引用**：参考 Claude / ChatGPT 的“+ → 从资料库添加”，以及 Cursor / Copilot 的“@ 引用”，两种入口都做。选中的资料以“引用”卡片的形式放进输入框，不需要重新上传。
3. **起始引导**：输入框下方不再放任何建议按钮。
4. **SAP 系统与模型**：两者都从后端实时获取，在弹层里选择。模型逐条消息生效，并记住上次的选择，做法和 SAP 系统一致。
5. **标题**：标题直接说明这里产出什么，不再提问。

## 4. 输入框

### 4.1 “+”菜单

点击“+”时弹出一个菜单（`BaseMenu`），不再直接打开文件选择框：

| 菜单项          | 行为                               | 快捷键           |
| --------------- | ---------------------------------- | ---------------- |
| 上传文件或图片  | 打开系统文件选择框（即原来的行为） | U                |
| 引用开发项资料… | 打开引用选择器（4.2）              | 在输入框中输入 @ |

菜单底部用一行灰色小字提示：“也可以直接粘贴截图或拖入文件”。

### 4.2 引用选择器

选择器是弹层（`Popover` + 可搜索列表，复用 ai-elements 的 `ModelSelector` 一类 Command 组件）。打开时实时请求一次后端，按以下分组列出：

| 分组               | 设计助手                                             | 开发助手                                 |
| ------------------ | ---------------------------------------------------- | ---------------------------------------- |
| 开发项             | 业务功能点（显示字数；没填时置灰，并提示“尚未填写”） | 业务功能点                               |
| 开发项附件         | 附件清单（文件名、大小、上传人和时间）               | 同左                                     |
| 设计成果           | ——                                                   | FSD 定稿版与最新版（各一项，显示版本号） |
| 本开发项的其他对话 | 其他设计对话里上传过的资料                           | 其他开发对话里上传过的资料               |

- 选择器支持多选，按名称搜索。已经引用的项会打勾，再点一次取消。
- 在输入框里输入 `@` 时，在光标处弹出同一个列表；`@` 后面接着输入的文字就是搜索词，回车选中，Esc 关闭。选中后删除 `@` 和后面的搜索词，在输入框上方的资料区加一张卡片。
- 引用卡片与上传附件放在同一个资料区，但样式不同：卡片带“引用”角标和来源图标，不显示“上传与解析”状态，因为引用的资料已经在服务端解析好了。
- 发送时，引用以 `references: [{ kind, id }]` 的形式随消息提交。服务端把它们复制成本次会话的附件（`source: 'item_file' | 'business_function' | 'fsd_revision' | 'session_file'`），之后与上传的附件走同一条路径：在“资料”弹层里显示，提供给助手阅读。同一份资料在同一会话里只复制一次。
- 起始页不自动带入任何资料（决策 2）。理由是：功能点质量参差，资料是否相关由顾问判断；自动带入还会让新对话在用户不知情时就占用模型上下文。

### 4.3 上下文选择器（SAP 系统与模型）

两个触发按钮使用同一个组件 `ContextPicker`：图标、名称、下拉箭头，字号统一用 `--text-xs`，颜色统一用 `muted-foreground`，并删除原生 `<select>`。

**SAP 系统**

- 每次打开弹层，都会实时请求一次项目里的 SAP 系统（`useProjectSap().reload()`）。
- 列表按“开发系统 / 测试系统”分组。每行显示 `SID client`、系统名称和登录状态。未登录的系统行尾有“登录”按钮，点击后在原位置打开 `SapLoginDialog`。
- 第一项是“默认 · S4H 100”，含义保持现状：留空表示由助手按用途取默认系统。
- 触发按钮上显示当前生效的系统。如果当前系统未登录，按钮上加一个黄色圆点，并提示“未登录，助手将无法读取”。

**模型**

- 新增接口 `GET {agentBase}/models`，需要 `agent.*:run` 权限。返回组织里未删除、已配置密钥的模型 `{ id, name, provider, isDefault }`，不含密钥和接入地址。默认模型排在第一位，并标注“默认”。工具调用能力目前不做探测（与默认模型一致），所以不按能力过滤，由助手在运行时报告服务商错误。
- 列表在每次打开弹层时实时获取。只有一个模型时，仍然可以打开弹层查看，但不能选其他模型。
- 选择结果保存在 `useAgentSession`，以组织、用户和助手为键，和 `sapSystemId` 的做法相同。发送消息时带上 `modelId`。
- 服务端校验：模型属于本组织、未删除、有密钥，否则返回 422（`code: MODEL_UNAVAILABLE`）“所选模型不可用，请改用默认模型”，前端随即清除记忆的选择。没有传 `modelId` 时用组织默认模型。`claimTurn` 已经记录了每一轮使用的模型，审计无需改动。
- 兼容性：不按厂商过滤（遵守模型兼容要求）。

### 4.4 底栏布局

```
[+]                                   [⛁ S4H 100 ▾] [◇ Gemini 3.1 Pro ▾] [⬆]
```

宽度不足 560px 时，模型名称收起成只显示图标，SAP 系统名称保留。

## 5. 顶栏

- 对话切换器：没有对话时显示“对话”（不再显示“新对话”），有对话时显示对话标题。右上角的“+ 新对话”保持不变。
- 成果面板按钮：在还没有任何成果版本时置灰，提示“助手写出第一版后可查看”。
- 开发项类型不支持开发时，“开发”标签保留但置灰，并提示“当前版本只支持报表与功能类开发项”，与清单和抽屉的表现一致。
- 用户对两个助手只有其中一个的使用权限时，另一个标签同样置灰，提示“你没有使用开发助手的权限”。

## 6. 权限、入口与抽屉成果区

### 6.1 权限点调整（先改契约与目录）

| 权限点           | 现在的含义                     | 调整后的含义                                       |
| ---------------- | ------------------------------ | -------------------------------------------------- |
| `agent.fsd:view` | 查看设计对话、功能说明书与批注 | 查看功能说明书（抽屉成果区）                       |
| `agent.fsd:run`  | 使用设计助手                   | 进入设计助手页：查看对话、发起对话、上传资料、批注 |
| `agent.dev:view` | 查看开发对话、开发方案与代码   | 查看开发方案与代码（抽屉成果区）                   |
| `agent.dev:run`  | 使用开发助手                   | 进入开发助手页                                     |

按照 AGENTS.md，变更顺序是：先改 `packages/contracts/access/catalog.mjs` 的说明文字，以及 [project-access-admin.md](project-access-admin.md) 中对应的表格；再修改路由。

### 6.2 后端

- 助手页的全部接口都改为要求 `:run`（在模块范围和“仅本人”的范围内），包括会话列表、会话详情、事件流、附件预览，以及 4.2 和 4.3 的两个新接口。没有权限返回 403；开发项不在可见范围内的，仍返回 404。
- 每个助手各自新增只读接口（实施时由一个合并接口改为按助手拆分，使权限点与模块一一对应）：
  - `GET {agentBase}/outputs`：要求本助手的 `:view`（不按模块收窄），返回 `{ latest, final }`，即本开发项全部会话中最新的版本和最新的“定稿”版本，各含会话、版本号、标签、时间和篇幅；
  - `GET {agentBase}/outputs/:sessionId/:version`：只返回成果正文（设计为 Markdown，开发为方案和代码），不含对话和批注；带 `?download=` 时作为文件下载（开发助手取值 `plan` 或 `code`）。
- 会话列表接口额外返回 `stages: { design, development }`，表示用户能否在本开发项使用两个助手，顶栏据此置灰另一个标签。
- 归档项目：有 `:run` 权限的人仍可进入并只读查看；写操作返回 409。

### 6.3 前端入口

- 开发清单行内的“设计/开发”图标和抽屉里的“设计/开发”按钮，都改为按 `mayOn('agent.fsd:run' | 'agent.dev:run', item)` 判断。没有权限时，按钮置灰并提示“你没有使用设计助手的权限，可在下方‘成果’中查看功能说明书”，不再隐藏，以免用户以为这个功能不存在。
- 修正发现 13：助手入口按本阶段负责人判断“仅本人”，没有负责人时取创建人（`packages/contracts/delivery/fields.mjs` 的 `stageOwner`，前后端共用）。开发项编辑仍按“创建人 + 各阶段负责人”判断，两者口径本来就不同。
- 直接访问助手页地址却没有 `:run` 权限时，页面显示空状态“你没有使用设计助手的权限”，并提供“查看功能说明书”按钮，跳转到 `/workspace/development-items?project=&item=&section=outputs`，打开开发清单和对应抽屉的成果区。旧的只读横幅只保留给归档项目。

### 6.4 抽屉“成果”区

抽屉锚点在“附件与活动”之前新增“成果”：

```
成果
┌ 功能说明书 ──────────────────────────────┐
│ 定稿 V3 · 10-15 张三     [查看] [下载]    │
│ 最新 V5 · 10-17 李四     [查看]           │
└──────────────────────────────────────────┘
┌ 开发方案与代码 ──────────────────────────┐
│ 尚无成果                                 │
└──────────────────────────────────────────┘
```

- 点“查看”时，在抽屉内展开只读正文（`ChatMarkdown` 渲染，开发助手的代码以 ABAP 代码块显示），不加载批注。
- “下载”沿用成果面板现有的导出格式。
- 有 `:run` 权限的用户额外显示“在助手中打开”，跳转到对应会话和版本。
- 某个助手没有 `:view` 权限时，整块不显示。

## 8. 验证要求

- 集成测试：每个助手页接口在只有 `:view` 时返回 403，在开发项超出范围时返回 404；`outputs` 只返回有权限的部分；`modelId` 指向停用的模型或其他组织的模型时返回 422；引用其他开发项的附件时返回 404。
- 前端单元测试：`ownersOf` 与后端规则一致；`@` 的触发、搜索、选中和关闭；引用卡片的去重。
- 浏览器验证：使用 `.env` 中的 TEST_USER，分别以有使用权限和只有查看权限的角色走一遍：清单按钮置灰、抽屉成果区、直接访问地址时的空状态、两个弹层的字号一致、在 1366×768 下的布局。
