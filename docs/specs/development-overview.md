# 开发概览设计

> 2026-10-30 设计，同日用户确认（第 11 节全部按建议）。状态：一至三期已全部实施（2026-10-30），实施记录见第 10.1、10.2 节；一期计划见 [开发概览一期实施计划](../plans/2026-10-30-development-overview-implementation.md)。由项目经理、交付总监/PMO、开发组长、一线开发、业务顾问、测试负责人、指标口径设计、可视化与数据架构八个角色分别提出问题与指标后汇总。数据现状见[开发清单重构设计](development-list.md)，权限见[项目主数据、权限与设置菜单设计](project-access-admin.md)，界面取值只用 [DESIGN.md](DESIGN.md) 的令牌。

## 1. 定位与原则

开发概览是“开发管理”下按项目角色展示的开发驾驶舱，服务实施方内部交付，遵守[平台定位方向决策](../architecture/2026-10-17-platform-positioning-decision.md)：

1. **零填报**：所有指标从平台已有的工作痕迹算出（开发清单、变更历史、设计/开发助手产出、项目里程碑），不为概览新增人工录入。
2. **每个数字都能落到具体开发项**：数字可点，跳到带同样条件的开发清单，条数一致。
3. **每个异常带下一步动作**：指派、进助手、处理批注、调整计划。
4. **按角色给首屏**，同一份数据、不同的提问顺序。
5. **不做**：客户视图、缺陷/测试用例/传输统计、个人排名与效率分（见第 9 节）。

## 3. 口径决定

| 主题         | 决定                                                                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 范围         | 只计 `deleted_at IS NULL` 的开发项；已取消阶段不进分母，单列“已取消 N”；四阶段全部取消的项记为“范围移出”                                                                                                       |
| 完成（两档） | **开发完成**：`development` 阶段已完成。**交付完成**：最后一个未取消阶段（通常是 `user_test`）已完成。开发项不设总状态字段                                                                                     |
| 风险（逾期） | 手工“已延误”**或**计划完成日已过且未完成/未取消，统一叫“风险”；界面分两个子标签：“已申报延误”“逾期未更新”。开发清单的“计划逾期”页签改用同一判定（现行 `overdue()` 按开发清单规格 Q3 排除“已延误”，需同步调整） |
| 进度         | 汇总只按状态计：人天加权完成率 = Σ已完成阶段人天 / Σ人天（仅 FSD、开发阶段）；测试阶段按件数。手工 `progress` 只在单项里显示，不汇总                                                                           |
| 阶段开始时间 | 补齐流水前依次取：首次变为“进行中”的事件时间 → 计划开始 → 上一阶段实际完成；估算值标“估算”                                                                                                                     |
| 周期与年龄   | 只报中位数和 P85，不报平均数                                                                                                                                                                                   |
| 判定函数     | 风险、完成、就绪等判定只写一份，放 `packages/contracts/delivery`，后端聚合与前端清单共用；测试断言概览数字与清单条数相等                                                                                       |

## 5. 亮点（建议优先做的“惊艳”部分）

1. **交接雷达**（M10 + M13）：FSD 一定稿，开发项自动进入组长的“可派”队列，附带涉及对象和冲突提示，一键指派开发负责人（写入变更历史）。
2. **健康度对账**（M23 + M24）：自报的绿黄红旁边是数据算出的信号色，不一致即高亮；PMO 不用听汇报就知道哪个项目报喜不报忧。
3. **冻结倒推线**（M03 + M22）：从开发冻结往回推，剩余人天与理想线、实际完成线画在一张图上，偏离一眼可见。
4. **SIT 进场预测**（M20 + M21）：按计划日期加上该项目历史的平均滞后（实际完成 − 计划完成），预测 SIT 开始那天各模块能进场几项。
5. **返工影响链**（M19）：定稿后又出新版本、且开发或测试已开始的项，自动标“需重测风险”，顾问、开发、测试看到同一条提示。
6. **一键周报草稿**：从本周事件差异生成“完成 N、新增 M、改期 K、下周到期”的内部周会草稿（不对客户）。

## 7. 接口与权限

- 后端是独立模块 `development-overview`（契约 3.6），只经 delivery、两个助手与 admin 的公开入口读取。**一期实施时的调整**：统计在应用层用共享判定 `packages/contracts/delivery/overview.mjs` 计算，而不是在 SQL 里另写一遍——每项目几百到几千个开发项，开销可忽略，换来概览数字与开发清单下钻条数由同一份代码决定；一期是一个接口，暂不做 ETag。
- 接口 `GET /api/projects/:projectId/development-overview` 返回：默认视角、可见范围（`scope`，下钻时并入筛选）、里程碑、计数（两档完成、移出范围）、四张卡片（各带下钻 `filter`）、阶段 × 状态、模块 × 阶段、本周关注、负载、开发组视图，有商务权限时另有预算。二期起按需拆出 `aging`、`flow`（快照序列）；跨项目组合视图另设 `/api/development-portfolio`。
- 权限点（已在 `packages/contracts/access/catalog.mjs` 登记，见第 11 节）：`delivery.overview:view`、`delivery.overview.team:view`、`delivery.portfolio:view`。`delivery.overview:view` 在 `SCOPED_PERMISSIONS` 中，按分配的模块范围与“仅本人负责”过滤统计范围。人天与预算字段另需 `project.commercial:view`，缺权限时**不返回字段**而非返回 0。
- 个人数据：持 `own_only` 分配的用户（如分包）只统计自己是创建人或阶段负责人的开发项；没有 `delivery.overview.team:view` 的人看不到他人姓名，负载中其他人合并为“其他成员”，页面不显示团队负载。
- 可见范围同时有多条分配、且限制不同（如 A 模块全部 + B 模块仅本人）时，`scope` 只能近似表达，下钻后的清单可能多出几项；一期接受此差异。
- 集成测试（`tests/integration/api/development-overview.test.mjs`）：未登录 401、缺权限 403、范围外项目 404、`own_only` 过滤、商务字段与他人姓名隐藏、每张卡片的数字与清单按同一筛选过滤后的条数一致。

- **下钻**：跳转开发清单并带条件，如 `/workspace/development-items?project=…&risk=1&phase=development&module=FICO&assignee=…`；开发清单改为 URL 参数优先于 sessionStorage 中保存的筛选，顶部显示“来自开发概览：<条件> · 清除”。现有字段表达不了的集合（如年龄 ≥ 30 天）用 `ids=` 传入。

## 9. 反指标配对与不做清单

配对展示，防止刷数：完成数 ↔ 完成后被改回的次数；风险数 ↔ “逾期未更新”占比与计划漂移；人天完成率 ↔ 单项人天中位数变化；吞吐 ↔ 积压年龄 P85。

不做：

- 个人排名、个人效率分、个人在线时长或活跃时间、按人统计 token/轮次/代码行数。
- 汇总手工 `progress`、平均周期、把估算值显示成精确值、缺数据时补 0。
- 缺陷数、测试用例通过率、实际工时、传输请求统计（平台无数据且不做缺陷管理）。
- 合成的开发项总状态字段、不能拆开的综合评分。
- 任何面向客户的视图或导出；饼图、仪表盘、新增颜色。

### 10.1 二期实施记录（2026-10-30）

- 迁移 `1792640000000_development-overview-records.sql`：D1 表 `app.development_phase_transition`（每次阶段状态变化一行；每个阶段第一行 `from_status` 为空，是新建时的状态；随开发项级联删除），由开发清单保存时在同一事务里写入（`delivery/store.mjs` 的 `applyChanges`、`insertItem`）；回填自 `development_event` 的 `*.status`，标 `backfilled`。D2 列 `development_item_phase.actual_start`：阶段第一次变为“进行中”或“已延误”时自动写当天，手填的优先；回填取流水中第一次进入这两个状态的日期；字段目录新增“实际开始日期”（抽屉、表格、Excel 随之出现），校验实际完成不早于实际开始。D3 列 `finalized_at`、`finalized_by`（FSD 文档版本与代码版本）：打“定稿”标签时写入，去掉标签时清空；旧的定稿不回填，统计时取版本生成时间并标“估算”。
- 接口新增：在制品年龄（M12，开始日取实际开始，否则计划开始并标估算；中位数与 P85）、开发助手覆盖（M14）、FSD 积压分段（M16：已逾期 / 7 天内 / 更远 / 未排期）、批注（M18，只算未归档对话）、FSD 返工（M19，定稿后的新版本数，开发或测试已开始时标“需重测”）、测试就绪度（M21）、“我的”待办与回应、顾问的三项待办、可指派的成员（仅持 `delivery.overview.team:view`）。交接雷达附开发对象与共用情况，可直接指派开发人员（走开发清单的修改接口与权限）。
- 前端：“我的”（今天先做、需要我回应、我的对象，不显示项目数字卡）、顾问、测试视角；开发组视角加交接雷达、在制品年龄点阵、开发助手覆盖。

### 10.2 三期实施记录（2026-10-30）

- **D4 改为回放**：累积流与燃尽不建每日快照表，而是在请求时用二期的阶段状态流水（D1）逐日回放每个阶段的状态——同样的数据，还能看到建表前（回填）的历史；最多回看 120 天。燃尽按各阶段**当前**的人天预估计算剩余量。
- **D5 计划基线**：迁移 `1792650000000_development-overview-baseline.sql` 新增 `development_item_phase.baseline_end`，阶段第一次填写计划完成日时自动记为基线，用户不能修改；回填取变更历史里最早的计划完成日，否则取当前值。与原设计“在里程碑节点冻结基线”不同：第一次承诺的日期更容易解释，也不需要 admin 模块写开发清单的表。M09 精确版即“现在的计划完成日 − 基线”。
- 接口在原响应中新增：`flow`（各阶段每日状态件数、每日剩余人天、理想线、冻结倒推所需节奏与近 4 周实际节奏）、`sitForecast`（按项目已完成阶段的平均滞后顺延未完成计划，预测 SIT 开始时各模块就绪数）、`week`（周报草稿的数据）、`planDrift`、`freshness`（M24）、`signal`（M23 计算信号及依据）、`guards`（第 9 节配对：近 30 天完成后改回的次数、近 30 天新增项与此前的人天中位数）。新接口 `GET /api/development-portfolio`（企业级 `delivery.portfolio:view`）：每个可见项目一行，含计算信号、最近一次自报健康度、风险、开发冻结、预算比例与最近更新。
- 计算信号规则：风险占比 ≥ 20% 红、≥ 10% 黄；有开发计划晚于开发冻结时黄，冻结在 14 天内（或已过未达成）时红；已计划人天超预算 10% 以上红、超出黄；开发清单 14 天以上没有更新黄。每条触发的规则都列出，不做不可拆的综合分。自报健康度比计算信号乐观时标“不一致”。
- 前端：项目视角加累积流图、燃尽与冻结倒推图（内联 SVG，不新增依赖）、计划漂移、数据信号；页头“周报草稿”生成可复制的内部周会文字；测试视角加 SIT 进场预测；开发组与测试视角显示“需重测”（返工影响链）；持企业级权限时出现“项目组合”视角，点行切到该项目。从概览打开的清单、开发项与助手页都在新标签中打开，概览标签保留。
- 修复（二期引入）：重新打开一个已完成的阶段时，自动写入的实际开始日期晚于原实际完成日期，保存被校验拒绝；现在这种情况不再自动写入开始日期。
- 端到端测试 `tests/e2e/development-overview-ui.test.mjs`（TEST-002）：用真实的统计函数生成概览数据，点“风险开发项”下钻，断言清单条数与卡片一致、项目已保存的筛选被替换、清除后恢复全部。
