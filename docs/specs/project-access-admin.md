# 项目主数据、权限体系、项目 SAP 系统与后台管理设计

> 2026-10-17 起草。状态：**草稿，待确认**（第 7 节）。依据[平台定位方向决策](../architecture/2026-10-17-platform-positioning-decision.md)：平台是实施方内部的交付生产工具，用户是实施方人员（含分包），客户方人员暂不是用户，但权限模型要能在以后为客户增加用户。本文以 SAP 实施项目经理的视角设计四件事：项目主数据（第 1 节）、权限体系（第 2 节）、项目 SAP 系统与个人凭据（第 3 节）、后台管理菜单（第 4 节）。后台的页面结构与交互对照 Plain 设置区实测（第 4.1 节）。本文本身不授权改代码：实施前须先按 AGENTS.md 修订[目录与依赖契约](../architecture/repository-contract.md)及检查规则；凡删除现有数据的步骤（第 3.6 节）须用户单独确认。

## 0. 设计原则

1. **服务端是唯一的权限裁决者**。菜单隐藏只是体验，每个接口都按权限点和数据范围校验；前端拿到的权限集只用于显示。
2. **概念与 SAP 一致**。实施团队人人熟悉 SAP 的 PFCG：单一角色、复合角色、权限对象与活动、组织级别。平台沿用这套说法，顾问不用重新学习。
3. **只授予、不禁止**。有效权限是所有角色的并集，没有“拒绝”规则。拒绝规则让人看不懂“为什么我没有权限”，SAP 也不这样做。
4. **权限点由代码定义，角色由管理员组合**。权限点是程序能检查的东西，管理员不能凭空新增；角色、复合角色、职位可以自由组合。
5. **可解释**。任何人对任何操作都能查到“哪个角色、哪次分配给了这项权限”，以及“为什么没有”。
6. **离场即失效**。分配带有效期；分包人员到期自动失去权限，SAP 凭据随之清除。
7. **凭据只属于本人**。SAP 用户和密码由用户本人输入，只用于本人的请求，管理员也不能代用。

## 1. 项目主数据

现有 `project` 只有编号、名称、客户、类型、状态、暂停标记、计划起止日期和说明。项目经理接手一个 SAP 项目，第一周要弄清楚的是：做什么系统、做哪些模块、按什么方法、关键日期在哪、谁负责什么、合同多少人天、现在健康不健康。下面按这七个问题分组。

### 1.1 基本信息

| 字段       | 说明                                                                                     | 存储                                     |
| ---------- | ---------------------------------------------------------------------------------------- | ---------------------------------------- |
| 项目编号   | 现有，企业内唯一                                                                         | `project.code`                           |
| 项目名称   | 现有                                                                                     | `project.name`                           |
| 简称       | 菜单、项目切换器、导出文件名使用，≤ 20 字                                                | 新增 `short_name`                        |
| 客户       | 现有                                                                                     | `project.customer_id`                    |
| 项目类型   | 新实施、全球模板推广（Rollout）、系统升级、S/4HANA 转换、功能增强、运维支持（AMS）、其他 | `project_type`，扩展取值（见 1.8）       |
| 实施方法论 | SAP Activate、ASAP、敏捷迭代、混合                                                       | 新增 `methodology`                       |
| 我方角色   | 总包、分包、与客户直签；分包时登记总包方名称                                             | 新增 `contract_role`、`prime_contractor` |
| 项目状态   | 筹备、实施中、已上线（上线支持期）、已结束、已归档；暂停是叠加标记                       | `status`，扩展取值（见 1.8）             |
| 项目说明   | 现有                                                                                     | `description`                            |
| 项目标识色 | 项目切换器与面包屑中的小色块，取自设计规范的固定色板                                     | 新增 `color`                             |

### 1.2 SAP 系统形态

这些属性决定助手能做什么、该怎么写代码，登记在项目上（平台定位决策 8.1）。

| 字段         | 取值 / 说明                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------- |
| SAP 产品     | ECC 6.0、S/4HANA（本地）、S/4HANA Cloud 私有云（RISE）、S/4HANA Cloud 公有云、BW/4HANA、其他      |
| 产品版本     | 文本，如 `S/4HANA 2023 FPS02`、`ECC 6.0 EHP8`                                                     |
| 部署形态     | 客户机房、私有云、公有云                                                                          |
| 实施模块     | 多选：FI、CO、MM、SD、PP、QM、PM、PS、WM/EWM、TM、HCM、BW、BTP 等；同时作为开发清单“模块”的可选项 |
| 主语言       | ZH、EN 等；SAP 登录语言与文档语言的默认值                                                         |
| 开发命名空间 | 如 `Z`、`Y`、`/ABC/`；开发助手生成对象名时使用                                                    |
| 默认开发包   | 如 `ZFI_REPORT`；写入开发方案的手工步骤                                                           |
| 开发框架类名 | `YCL_FRH_REPORT` 及工具类、异常类在本项目中的名称（平台定位决策 8.6），默认值取企业设置           |
| 传输方式     | ChaRM、手工传输请求；只登记，不管理                                                               |

设计要点：助手在第一轮读取这些属性。例如项目是公有云时，开发助手明确告知“经典报表不可用”；开发命名空间不是 `Z` 时，生成的对象名自动遵守。

### 1.3 阶段与里程碑

项目阶段按 SAP Activate 预置（方法论不同时可改名、增删），里程碑是项目经理盯得最紧的日期。

**阶段**（`project_phase`，每个项目一组，默认 6 行）：发现（Discover）、准备（Prepare）、探索（Explore，蓝图）、实现（Realize）、部署（Deploy）、运行（Run，上线支持）。每行：计划开始、计划结束、实际开始、实际结束、状态（未开始 / 进行中 / 已完成）。项目的“当前阶段”由状态推出，不单独维护。

**里程碑**（`project_milestone`）：预置以下 9 个，可增删改：

| 里程碑              | 所在阶段 | 说明                                |
| ------------------- | -------- | ----------------------------------- |
| 项目启动会          | 准备     | Kick-off                            |
| 蓝图签字            | 探索     | 业务蓝图 / Fit-to-Standard 结论确认 |
| 开发冻结            | 实现     | 此后只修缺陷，不接新开发            |
| 集成测试（SIT）开始 | 实现     |                                     |
| 集成测试（SIT）结束 | 实现     |                                     |
| 用户验收（UAT）完成 | 部署     |                                     |
| 切换开始            | 部署     | Cutover                             |
| 上线                | 部署     | Go-live，项目最重要的日期           |
| 上线支持结束        | 运行     | Hypercare 结束，转运维或结项        |

每个里程碑：名称、阶段、计划日期、实际日期、状态（未到 / 已达成 / 延期）、说明。计划日期晚于今天且未达成时自动标“即将到期”（7 天内）或“已延期”。

**和开发清单的联动**：开发冻结、SIT 开始是开发清单最关心的两个日期。开发清单页头显示“距开发冻结 12 天”，计划完成日期晚于开发冻结的开发项标黄。这是项目经理每天都会看的提示。

### 1.4 团队与干系人

**我方关键岗位**（项目上的“负责人”字段，取项目成员）：项目经理、项目总监 / 交付负责人、方案架构师、开发组长、Basis 负责人。

**模块负责人**（`project_module_lead`）：每个实施模块一位负责顾问。开发清单按模块派活、FSD 审阅时默认找这个人。

**客户方联系人**（`project_contact`）：客户方人员不是平台用户，以通讯录方式登记：姓名、职务、部门、角色（甲方项目经理、IT 负责人、业务负责人、关键用户、其他）、负责模块、电话、邮箱、备注。开发清单的“业务 Owner”以后可以从这里选择，同时保留手填。联系方式属于个人信息，只对有“查看干系人”权限的成员显示。

### 1.5 规模与商务

商务字段敏感，单独授权（权限点 `project.commercial:view` / `:edit`，见 2.5）。

| 字段         | 说明                                            |
| ------------ | ----------------------------------------------- |
| 合同编号     | 文本                                            |
| 合同模式     | 固定总价、人天计价、按实际工时                  |
| 合同人天     | 总人天；可按模块拆分（`project_effort_budget`） |
| 开发人天预算 | RICEFW 开发部分的人天                           |
| 已计划人天   | 自动汇总：开发清单 FSD + 开发阶段的人天预估     |
| 计划团队规模 | 人数                                            |

“已计划人天 / 开发人天预算”直接显示为进度条，超出预算标红。这是开发清单与合同口径之间唯一的桥，也是项目经理最常被问到的数字。

### 1.6 项目健康度

项目经理每周更新一次，作为项目列表与工作台的核心信号：

- 四个维度：进度、范围、成本、质量，各取 绿 / 黄 / 红；综合状态由项目经理判定（不自动取最差值，因为红黄的含义需要人来解释）。
- 每次更新记录日期、更新人、一句话说明，形成历史（`project_health`），可以回看趋势。
- 超过 14 天未更新时提示“健康度已过期”。

### 1.7 项目扩展字段

不同企业关心的属性不同。参照 Plain 的 Tenant fields 与现有开发清单自定义列（`development_field`），企业管理员可以定义项目扩展字段（`project_field`，企业级定义，取值存 `project.custom_values`），类型沿用开发清单的 9 种。这样新增“行业”“区域”“销售负责人”之类的字段不用改表。

### 1.8 存储与迁移

- 主表 `project` 增加 1.1、1.2、1.5 的标量字段与 `custom_values`；阶段、里程碑、模块负责人、联系人、人天拆分、健康度历史各为子表，沿用 `(organization_id, project_id)` 复合外键与 `row_version` 乐观锁。
- 状态取值：现有 `preparing / active / completed / archived` 映射为 筹备 / 实施中 / 已结束 / 已归档，新增 `live`（已上线）。类型取值：现有 `implementation / rollout / enhancement / support / migration / other` 保留，新增 `upgrade`、`conversion`。只新增取值，不改写已有数据。
- 已归档项目只读（平台定位决策第 7 节）：所有写接口对归档项目返回 409，项目切换器默认不显示。

## 2. 权限体系

### 2.1 概念

```text
用户 ──任职──> 职位 ──默认──> 复合角色（模板）
  │
  ├──企业级分配──> 角色（单一 / 复合）+ 数据范围（全部项目 / 指定客户 / 指定项目）+ 有效期
  │
  └──项目成员──> 项目内角色（单一 / 复合）+ 模块范围 + 有效期
                       │
单一角色 = 一组权限点   复合角色 = 一组单一角色（只嵌套一层）
权限点 = 对象 : 活动（菜单、操作、字段三类）
```

| 概念     | 对应 SAP        | 说明                                                                                 |
| -------- | --------------- | ------------------------------------------------------------------------------------ |
| 权限点   | 权限对象 + 活动 | 程序检查的最小单位，如 `delivery.item:edit`。由代码登记，管理员不能新增              |
| 单一角色 | 单一角色        | 一组权限点，并声明作用层级：企业级（与具体项目无关）或项目级（在某个项目内生效）     |
| 复合角色 | 复合角色        | 一组同层级的单一角色，只嵌套一层（复合角色不能再包含复合角色），用于对应实际岗位     |
| 职位     | HR 职位         | 用户在实施方的岗位（项目经理、FICO 顾问、ABAP 开发……），带一组默认角色；不是权限本身 |
| 数据范围 | 组织级别        | 角色在哪些数据上生效：企业级分配指定项目范围；项目内分配可限定模块、限定“仅本人负责” |
| 分配     | 用户分配        | 用户 × 角色 × 数据范围 × 有效期，是唯一产生权限的东西                                |

### 2.2 权限点

命名 `领域.对象:活动`。活动统一为：`view` 查看、`create` 创建、`edit` 修改、`delete` 删除、`import` 导入、`export` 导出、`run` 使用 / 执行、`finalize` 定稿、`manage` 管理（含配置）。

权限点分三类，在角色编辑器里以一棵树展示（菜单 → 页面 → 操作 / 字段），勾选下级时自动勾选上级菜单，取消菜单时同时取消其下所有项：

| 类型 | 作用                           | 例                        |
| ---- | ------------------------------ | ------------------------- |
| 菜单 | 决定菜单与页面是否可见         | `menu.delivery.items`     |
| 操作 | 决定按钮是否可用、接口是否放行 | `delivery.item:delete`    |
| 字段 | 决定敏感字段是否可见、可改     | `project.commercial:view` |

菜单权限不单独授予：页面需要的查看权限即菜单权限，避免“看得到菜单、点进去 403”。树上菜单节点是其下操作的汇总勾选框。

权限点登记在 `packages/contracts`（前后端共用一份），附中文名称、说明、所属菜单、层级（企业级 / 项目级）。数据库只存权限点编码；保存角色时校验编码存在。程序升级删除某个权限点时，迁移脚本同步从角色中移除并记审计。

### 2.3 权限点目录

**项目级**（在某个项目内生效）：

| 领域          | 权限点                                                                                                                                                                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目          | `project:view` 查看项目、`project:edit` 修改基本信息与系统形态、`project.plan:edit` 维护阶段与里程碑、`project.health:edit` 更新健康度、`project.contact:view` / `:edit` 客户联系人、`project.commercial:view` / `:edit` 商务字段、`project:archive` 归档 |
| 项目成员      | `project.member:view`、`project.member:manage`（增删成员、分配项目内角色；敏感角色的分配限制见 2.7）                                                                                                                                                      |
| 项目 SAP 系统 | `project.sap:view`、`project.sap:manage`（增删改系统、设默认）                                                                                                                                                                                            |
| 开发清单      | `delivery.item:view` / `:create` / `:edit` / `:delete` / `:import` / `:export`、`delivery.item.phase:edit`（修改阶段负责人、计划、进度）、`delivery.config:manage`（自定义列、标签、模块选项）                                                            |
| FSD 设计助手  | `agent.fsd:view` 查看会话与文档、`agent.fsd:run` 发起与继续对话、`agent.fsd:finalize` 定稿、`agent.fsd:comment` 批注                                                                                                                                      |
| ABAP 开发助手 | `agent.dev:view`、`agent.dev:run`、`agent.dev:finalize`、`agent.dev:comment`、`agent.dev.code:sync`（上传或从 SAP 同步代码）                                                                                                                              |
| 测试助手      | `agent.test:view`、`agent.test:run`（顾问测试、IT/用户测试开放时启用）                                                                                                                                                                                    |
| SAP 访问      | `sap.dev:read`（助手读取开发系统）、`sap.qas:read`（读取测试系统）、`sap.test_data:create`（在测试系统创建测试数据，现有功能，会写入 SAP）                                                                                                                |
| 产出物        | `deliverable:export`（按项目导出 FSD、代码与开发清单）                                                                                                                                                                                                    |

**企业级**（与具体项目无关，或跨项目）：

| 领域       | 权限点                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------- |
| 企业       | `org.profile:view` / `:edit`、`org.security:manage`（密码、会话、SAP 凭据保存策略）      |
| 客户与项目 | `customer:view` / `:manage`、`project:create`、`project.field:manage`（项目扩展字段）    |
| 用户与职位 | `user:view` / `:create` / `:edit` / `:disable`、`user.password:reset`、`position:manage` |
| 角色与权限 | `role:view` / `:manage`、`role.assignment:manage`、`access.report:view`（权限报表）      |
| 模型       | `model:view` / `:manage`                                                                 |
| 智能体配置 | `agent.config:manage`（提示词、框架默认类名）                                            |
| 审计       | `audit:view`、`audit.comment:create`、`audit:export`                                     |
| 运维       | `ops.run:view`（运行记录）、`ops.diagnostics:run`（SAP 连接诊断，原“技术验证”）          |

企业级角色分配时带**项目范围**（全部项目 / 指定客户的项目 / 指定项目），在此范围内同时获得角色中包含的项目级权限点。这用于交付总监、PMO 这类跨项目查看的岗位，不必把他们加进每个项目。

### 2.4 数据权限

数据权限回答“在哪些数据上”，分三层，逐层收窄：

1. **项目范围**：用户能进入哪些项目 = 作为成员加入的项目 ∪ 企业级分配的项目范围。项目列表、项目切换器、全局搜索都按此过滤。不在范围内的项目，接口一律返回 404（不暴露存在）。
2. **模块范围**：项目内分配可限定模块（如只限 FI、CO）。限定后，开发清单中其他模块的开发项**可看不可改**：顾问需要了解全貌（跨模块集成很常见），但只能改自己模块的。未限定即全部模块。
3. **本人范围**：项目内分配可勾选“仅本人负责”。勾选后，只能修改自己是阶段负责人的开发项阶段、只能对自己负责的开发项发起助手。用于分包开发人员。

字段权限（商务字段、联系人）在此之上单独控制。

### 2.5 预置角色

预置角色标“系统”，不可删除、不可修改，可以“复制为新角色”后调整（同 Plain 的 Owner / Admin 与 SAP 的 `SAP_ALL` 做法）。

**企业级单一角色**：

| 编码                | 名称       | 主要权限                                       |
| ------------------- | ---------- | ---------------------------------------------- |
| `SYS_SUPER_ADMIN`   | 超级管理员 | 全部权限；企业至少保留一名有效的超级管理员     |
| `SYS_USER_ADMIN`    | 用户管理员 | 用户、职位、重置密码                           |
| `SYS_ROLE_ADMIN`    | 权限管理员 | 角色、分配、权限报表                           |
| `SYS_PROJECT_ADMIN` | 项目管理员 | 客户、建项目、项目扩展字段                     |
| `SYS_PLATFORM`      | 平台配置员 | 模型、智能体配置、安全策略、连接诊断、运行记录 |
| `SYS_AUDITOR`       | 审计员     | 审计查看、评论、导出，权限报表；只读           |

**项目级单一角色**：

| 编码             | 名称         | 权限点                                                                                            |
| ---------------- | ------------ | ------------------------------------------------------------------------------------------------- |

- 一个用户一个主职位，另记“擅长模块”（多选），加入项目时用于默认模块范围。
- 职位的默认角色只在**分配时**带出，之后各自独立：修改职位的默认角色不会回溯改动已有分配（避免一次修改悄悄改变几十人的权限）。界面提供“按职位默认值重新对齐”的显式操作，先预览差异再执行。
- 用户增加“人员类型”：员工、分包、外部（为将来的客户用户预留，暂不开放）。分包与外部人员的任何分配都必须设结束日期。

### 2.7 授权规则

- **有效权限** = 未过期的企业级分配（含其项目范围）∪ 该项目内未过期的分配，取并集后按模块范围、本人范围收窄。
- **不能越权授权**：持有 `project.member:manage` 的人可以在本项目分配任意项目级角色，但角色中含**敏感权限点**（`project.member:manage`、`project.commercial:*`、`project:archive`）时，分配人自己必须在本项目持有这些权限点；任何人都不能给自己增加角色或延长有效期。
- **超级管理员保护**：不能删除或停用最后一名有效的超级管理员；超级管理员不能取消自己的超级管理员角色。
- **有效期**：分配有开始与结束日期；到期由定时任务失效（并在每次检查时按时间判定，不依赖定时任务准时执行）。到期前 7 天提醒项目经理续期。
- **离场**：停用用户或移出项目时，立即撤销会话中的相应权限，并删除该用户在相关项目 SAP 系统上保存的凭据（第 3.4 节）。
- **生效时机**：分配变化后，下一个请求即按新权限执行。服务端按“用户权限版本号”缓存有效权限，变更时版本号加 1。

### 2.8 可解释与报表

参照 SAP 的 SUIM，这是权限体系让人放心的关键：

- **用户权限视图**：某用户在某项目的全部有效权限点，每项注明来自哪个角色、哪次分配、有效期至何时。
- **权限反查**：某个权限点（如 `project.commercial:view`）在某项目或全企业有哪些人持有。
- **“以他人视角预览”**：管理员选择一名用户和一个项目，以只读方式看到该用户看到的菜单和按钮（不代用其 SAP 凭据，不执行写操作）。
- **无权限说明**：接口返回 403 时附带缺少的权限点；页面显示“需要‘开发清单管理’权限，请联系项目经理”，而不是一句“无权限”。
- **审计**：角色的增删改、分配与撤销、职位默认值变更、预览他人视角，全部写入审计日志。

## 3. 项目 SAP 系统与个人凭据

### 3.1 现状与问题

- SAP 系统登记在企业级（`sap_system`，含所属客户与对客户的临时授权 `sap_system_grant`），项目按 DEV / QAS / PRD 三个固定环境各选一个系统（`project_sap_config`），每个环境只能一个。
- 项目级配置可以保存共享的 SAP 用户与密码；个人配置可覆盖。测试系统的个人用户和密码只存在 API 进程内存，最长 12 小时，重启即失。
- 问题：一个项目常有多套开发 / 测试系统（S/4 与 BW、主系统与沙箱、多个 Client）；共享账号在 SAP 审计中追溯不到人；平台定位决策已确定不连 PRD。

### 3.2 项目 SAP 系统

每个项目维护自己的 SAP 系统清单（`project_sap_system`），不再引用企业级系统：

| 字段         | 说明                                         |
| ------------ | -------------------------------------------- |
| 名称         | 如“S/4 开发 100”，在助手与开发清单中显示     |
| 用途         | 开发系统、测试系统（不允许生产系统）         |
| 系统标识 SID | 3 位，如 `S4D`                               |
| 产品         | S/4HANA、ECC、BW 等；默认取项目的 SAP 产品   |
| ADT 地址     | `https://host:port`，助手经 ADT 访问         |
| Client       | 3 位数字，必填                               |
| 默认登录语言 | 默认取项目主语言                             |
| 说明         | 用途说明，如“FI 沙箱，数据每周刷新”          |
| 默认         | 每种用途最多一个默认系统（部分唯一索引保证） |
| 状态         | 启用、停用；停用后助手不可选，历史记录保留   |

**不保存任何用户名和密码。**同一 SID 的不同 Client 是不同的记录。

- **默认系统**：项目必须有一个默认开发系统才能使用开发助手；默认测试系统用于测试数据与测试助手。
- **开发项指定系统**：开发项可选“目标开发系统”（默认取项目默认开发系统），用于一个项目同时开发 S/4 与 BW 对象的情况；开发助手、代码同步、对象核查都使用该系统。
- **会话内切换**：助手会话可在项目已启用的同用途系统间切换，切换写入对话记录；会话记录每次 SAP 调用实际使用的系统与 Client。
- **复制**：新建项目时可从同一客户的其他项目复制系统清单。

### 3.3 个人凭据

各系统的 SAP 用户与密码由用户本人输入。首次使用某系统时弹出登录框：SAP 用户、密码、保存方式。

| 保存方式     | 存放位置                       | 有效期                                               | 适用                     |
| ------------ | ------------------------------ | ---------------------------------------------------- | ------------------------ |
| 不保存       | API 进程内存，仅本次请求链使用 | 当前助手运行结束                                     | 公用电脑、高敏系统       |
| 本次登录有效 | API 进程内存                   | 平台退出登录、会话过期或服务重启时失效               | 现有行为                 |
| 加密保存     | 数据库，加密                   | 企业安全策略规定的天数（默认 30 天），到期需重新输入 | 日常频繁使用（默认选项） |

“加密保存”只在企业安全策略允许时出现（第 3.4 节）。

### 3.4 安全策略

**加密**

- 信封加密：每条凭据一个随机数据密钥，AES-256-GCM 加密密码；数据密钥再由主密钥加密。主密钥来自部署环境（现有 `SAP_CREDENTIAL_KEY`），后续可接云密钥管理服务；数据库中只有密文。
- 附加认证数据绑定 `用户 ID + 项目 SAP 系统 ID + ADT 地址 + Client + SAP 用户`：密文复制到别的行无法解密；系统地址或 Client 被修改后，旧凭据自动失效，要求重新输入。
- 主密钥轮换：保存密钥版本号，轮换时后台逐条重加密，旧版本密钥保留到全部重加密完成。

**使用**

- 只用于本人发起的请求（本人的助手运行、本人的连接测试）。管理员、项目经理和“以他人视角预览”都不能使用他人的凭据。
- 接口从不返回密码或密文，只返回“已保存 · SAP 用户 · 保存于 · 到期于 · 最近成功使用”。
- 日志、错误信息、审计、模型上下文中都不出现密码。

**SAP 侧的特殊情况**（实施顾问都踩过的坑）

- **防止锁定 SAP 用户**：SAP 默认连续 3～5 次密码错误就锁定用户。已保存的凭据一旦登录失败，立即标为失效、停止使用，并提示用户重新输入；平台绝不自动重试错误的密码。
- **密码过期**：SAP 要求定期改密码。返回“密码已过期 / 需修改”时，提示用户先在 SAP GUI 中修改，再回平台更新；平台不代为修改 SAP 密码。
- **用户被锁定**：明确提示“SAP 用户已锁定，请联系 Basis 解锁”，而不是笼统的“连接失败”。

**撤销**

- 用户可在“我的 SAP 凭据”中查看与删除自己保存的全部凭据。
- 用户被停用、移出项目，或系统被删除 / 停用、地址或 Client 被修改时，相关凭据立即删除或失效。
- 管理员可按用户或按系统强制清除（不查看内容），用于离职与安全事件。

**企业安全策略**（`org.security:manage`）

| 策略                  | 默认              |
| --------------------- | ----------------- |
| 允许加密保存 SAP 密码 | 允许              |
| 加密保存的最长天数    | 30 天             |
| 闲置自动失效          | 14 天未使用即失效 |
| 分包人员允许加密保存  | 不允许            |

**审计**：凭据的保存、使用失败、失效、删除、强制清除写入审计日志（不含内容）；成功使用只更新“最近成功使用”时间，不逐次写日志。

### 3.5 本地开发

现有本地开发的凭据文件（`SAP_MCP_PROFILE_FILE`，契约 3.4）保留，仅非生产环境有效，匹配到相同 ADT 地址与 Client 时使用，便于自动化测试。

### 3.6 迁移

| 现有                                       | 处理                                                                              |
| ------------------------------------------ | --------------------------------------------------------------------------------- |
| `sap_system`（企业级系统）                 | 被各项目引用的 DEV / QAS 系统复制为对应项目的 `project_sap_system` 记录，设为默认 |
| `project_sap_config` 的 DEV / QAS 配置     | Client、语言并入上条记录                                                          |
| `project_sap_config` 的 PRD 配置           | 不迁移                                                                            |
| 项目级共享 SAP 用户与密码                  | 不迁移。**删除共享密码属于删除数据，须用户单独确认**                              |
| `user_project_sap_config` 的个人用户与密码 | 个人用户迁移为对应系统的凭据（保存方式为“加密保存”，到期按策略）；用户可随时删除  |

规则：

- **按权限显示**：没有任何可见项的分组整组隐藏；普通开发顾问只看到“个人”和“项目”下的只读项。
- **规划中的页面不进菜单**：占位页不再出现在正式菜单里，上线时再加入。
- **项目分组跟随当前项目**：分组标题显示当前项目简称，点击可切换；项目经理不必进“企业 → 项目”就能管理自己的项目。“企业 → 项目”面向管理员，用于建项目、归档、跨项目查看。
- **搜索设置**：按菜单名称、说明与设置项名称搜索（同 Plain），回车直达。
- **旧路由跳转**：`/workspace/organization`、`/workspace/members`、`/workspace/connections`、`/workspace/technical-verification`、`/settings` 跳转到新地址，不保留旧页面。

### 4.4 页面形态

全部按 Plain 设置区的形态与 [DESIGN.md](DESIGN.md) 的令牌实现：

- **概览**：按上面的分组，每组标题 + 一句说明 + 两列卡片；卡片只显示当前用户有权限的项。项目分组的卡片附带状态，例如“SAP 系统 · 2 个开发、1 个测试”“里程碑 · 上线还有 46 天”。
- **列表页**（用户、角色、项目、成员）：标题 + 说明 + 右上墨色主按钮；页签（如用户的“在职 / 已停用 / 即将到期”）；统计格（如角色页“系统角色 16 · 自定义 3 · 未使用 1”）；搜索；行尾 ⋯ 与 ›。
- **详情页**：“← 返回”+ 标题 + 说明；按卡片分组，每张卡片底部右下角“保存”，只保存本卡片（不做整页大表单）。
- **角色编辑**：左侧权限点树（菜单 → 页面 → 操作 / 字段，带搜索与“只看已选”），右侧显示所选节点的说明与“持有此权限的角色”；复合角色编辑为单一角色的勾选列表，并实时显示合并后的权限点数。
- **成员与权限**：成员行显示头像、姓名、职位、项目内角色标签、模块范围、到期日；即将到期的行显示黄色标签。分配对话框里先选角色（单选卡片，附一句说明，同 Plain），再选模块范围与有效期；底部预览“将获得的权限”摘要。
- **用户权限视图**：用户详情页的“权限”页签，按项目分组展示有效权限点及来源（2.8）。

## 5. 接口与实施要点

- **权限检查唯一入口**：服务端提供 `authorize(req, permission, { projectId, module, ownerId })`，替换现有按“是否管理员”判断的 `adminContext.authorize` 和各模块各自的成员检查。各模块通过 `admin`（或新拆出的 `access` 模块，契约修订时确定）的公开接口调用，不直接查角色表。
- **会话接口**返回当前用户的企业级权限点与可进入项目列表；进入项目时取该项目的有效权限点。前端只据此渲染菜单与按钮。
- **一致性**：角色、分配的写操作沿用现有的企业级咨询锁与 `row_version` 乐观锁，以及“最后一名超级管理员”的检查。
- **测试**：权限点目录与各接口的绑定关系做成表驱动测试：每个写接口在缺少对应权限点时必须返回 403，在范围外项目必须返回 404。

## 7. 待确认问题

1. **权限模块归属**：权限内核放在现有 `admin` 模块，还是新拆一个 `access` 模块（管理界面仍在 `admin`）？建议：新拆 `access`，因为所有业务模块都要调用它，而 `admin` 是一组管理页面的后端，依赖方向不同。
2. **迁移时现有项目成员的角色**：建议全部迁为 `C_PM`，保证迁移当天无人失去权限，再由管理员收窄；还是按其在开发清单中担任的阶段负责人推断（业务顾问 → `C_FUNC`，开发人员 → `C_DEV`）？建议前者，推断容易出错。
3. **项目级共享 SAP 密码**：迁移时删除（第 3.6 节）。这是删除现有数据，需要你确认。
4. **企业级 SAP 系统清单**：项目自带系统后，企业级 `sap_system` 与 `sap_system_grant` 停用。是否保留一个只读的“企业 SAP 系统一览”（汇总各项目登记的系统，便于 Basis 查看），还是彻底去掉？建议保留只读汇总，不再单独维护。
5. **测试数据创建**：现有的测试数据功能会在测试系统中执行代码写入数据，与平台定位决策“不向 SAP 写入”的表述不一致。建议在决策中明确为例外：只限测试系统、需 `sap.test_data:create` 权限、逐次授权并留痕（现有做法）。
6. **加密保存的默认天数**：建议 30 天、闲置 14 天失效、分包人员不允许保存。
7. **统一身份登录（企业微信、钉钉、飞书、AD）**：本文不含。是否列入后续？Plain 的 SSO 在 Admin 分组第一屏，若列入，“企业 → 安全策略”中预留位置。
