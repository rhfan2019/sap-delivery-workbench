# 项目主数据、权限体系、项目 SAP 系统与设置菜单

> 2026-10-17 起草，同日定稿；2026-10-18 实施完成。状态：**已实施**，第 7 节为用户对待确认问题的答复，第 8 节为执行记录。依据[平台定位方向决策](../architecture/2026-10-17-platform-positioning-decision.md)：平台是实施方内部的交付生产工具，用户是实施方人员（含分包），客户方人员暂不是用户，但权限模型要能在以后为客户增加用户。本文以 SAP 实施项目经理的视角设计四件事：项目主数据（第 1 节）、权限体系（第 2 节）、项目 SAP 系统与个人凭据（第 3 节）、设置菜单（第 4 节）。设置区的页面结构与交互对照 Plain 设置区实测（第 4.1 节）。目录与依赖按[契约](../architecture/repository-contract.md) 1.18 执行。

## 0. 设计原则

权限体系采用 Web 应用的通行做法：基于角色的访问控制（RBAC，参照 NIST RBAC 模型），角色按资源范围绑定（与 GitHub 的组织 / 仓库角色、Kubernetes 的 Role 与 RoleBinding 同一思路），数据范围用附加条件表达（属性条件，ABAC 的最小用法）。

1. **默认拒绝，服务端裁决**。没有授予就没有权限；菜单隐藏只是体验，每个接口都在服务端按权限点和数据范围校验，前端拿到的权限集只用于显示。
2. **集中决策**。所有模块通过同一个权限内核（`access` 模块）判断“谁、在哪个项目、能不能做这件事”，不各自写成员或管理员判断。
3. **只授予、不禁止**。有效权限是全部有效分配的并集，没有“拒绝”规则；拒绝规则会让“为什么我没有权限”难以解释。
4. **权限点由代码定义，角色由管理员组合**。权限点是程序能检查的东西（`资源:动作`），管理员不能凭空新增；角色、复合角色、职位可以自由组合。
5. **最小权限，不能越权授予**。任何人都不能把自己没有的权限授予别人，也不能给自己加权限。
6. **有时限的访问**。分配带有效期，到期即失效（每次检查时按日期判断，不依赖定时任务）；分包与外部人员必须设结束日期。
7. **可解释、可审计**。任何人对任何操作都能查到“哪个角色、哪次分配给了这项权限”，被拒绝时知道缺的是哪一项；所有授权变更写入审计日志。
8. **凭据只属于本人**。SAP 用户和密码由用户本人输入，只用于本人的请求，管理员也不能代用。

## 1. 项目主数据

原有 `project` 只有编号、名称、客户、类型、状态、暂停标记、计划起止日期和说明。项目经理接手一个 SAP 项目，第一周要弄清楚的是：做什么系统、做哪些模块、按什么方法、关键日期在哪、谁负责什么、合同多少人天、现在健康不健康。下面按这七个问题分组。

### 1.1 基本信息

| 字段       | 说明                                                                                     | 存储                                     |
| ---------- | ---------------------------------------------------------------------------------------- | ---------------------------------------- |
| 项目编号   | 企业内唯一                                                                               | `project.code`                           |
| 项目名称   |                                                                                          | `project.name`                           |
| 简称       | 页头的项目切换器使用，≤ 20 字                                                            | `short_name`                             |
| 客户       |                                                                                          | `customer_id`                            |
| 项目类型   | 新实施、全球模板推广（Rollout）、系统升级、S/4HANA 转换、功能增强、运维支持（AMS）、其他 | `project_type`                           |
| 实施方法论 | SAP Activate、ASAP、敏捷迭代、混合                                                       | `methodology`                            |
| 我方角色   | 总包、分包、与客户直签；分包时登记总包方名称                                             | `contract_role`、`prime_contractor`      |
| 项目状态   | 筹备、实施中、已上线（上线支持期）、已结束、已归档；暂停是叠加标记                       | `status`、`is_paused`                    |
| 计划起止   | 项目合同周期                                                                             | `planned_start_date`、`planned_end_date` |
| 项目说明   |                                                                                          | `description`                            |

### 1.2 SAP 系统形态

这些属性决定助手能做什么、该怎么写代码，登记在项目上（平台定位决策 8.1）。助手在每一轮的背景信息中读到它们。

| 字段         | 取值 / 说明                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------- |
| SAP 产品     | ECC 6.0、S/4HANA（本地）、S/4HANA Cloud 私有云（RISE）、S/4HANA Cloud 公有云、BW/4HANA、其他    |
| 产品版本     | 文本，如 `S/4HANA 2023 FPS02`、`ECC 6.0 EHP8`                                                   |
| 部署形态     | 客户机房、私有云、公有云                                                                        |
| 实施模块     | 多选：FI、CO、MM、SD、PP、QM、PM、PS、WM、EWM、TM、HCM、BW、BTP；同时作为成员“模块范围”的可选项 |
| 主语言       | ZH、EN 等两位字母；SAP 系统登录语言的默认值                                                     |
| 开发命名空间 | 如 `Z`、`Y`、`/ABC/`；开发助手生成对象名时遵守                                                  |
| 默认开发包   | 如 `ZFI_REPORT`；写入开发方案的手工步骤                                                         |
| 传输方式     | ChaRM、手工传输请求；只登记，不管理                                                             |

开发框架类名的项目级配置（平台定位决策 8.6）随开发助手的框架加载一并实现，暂不在本批。

### 1.3 阶段与里程碑

项目阶段按 SAP Activate 预置，里程碑是项目经理盯得最紧的日期。

**阶段**（`project_phase`，建项目时生成 6 行）：发现（Discover）、准备（Prepare）、探索（Explore，蓝图）、实现（Realize）、部署（Deploy）、运行（Run，上线支持）。每行：计划开始、计划结束、实际开始、实际结束、状态（未开始 / 进行中 / 已完成）。阶段名称可改；项目的“当前阶段”取第一个“进行中”的阶段，不单独维护。

**里程碑**（`project_milestone`）：建项目时预置以下 9 个，可增删改：

| 里程碑              | 所在阶段 | 说明                                |
| ------------------- | -------- | ----------------------------------- |
| 项目启动会          | 准备     | Kick-off                            |
| 蓝图签字            | 探索     | 业务蓝图 / Fit-to-Standard 结论确认 |
| 开发冻结            | 实现     | 此后只修缺陷，不接新开发            |
| 集成测试（SIT）开始 | 实现     |                                     |
| 集成测试（SIT）结束 | 实现     |                                     |
| 用户验收（UAT）完成 | 部署     |                                     |
| 切换开始            | 部署     | Cutover                             |
| 上线                | 部署     | Go-live，项目最重要的日期           |
| 上线支持结束        | 运行     | Hypercare 结束，转运维或结项        |

每个里程碑：名称、阶段、计划日期、实际日期、说明。状态由日期推出：有实际日期为“已达成”；计划日期已过而未达成为“已延期”；7 天内到期为“即将到期”；其余为“未到”。预置里程碑带固定标识（如 `code_freeze`、`go_live`），供其他页面引用。

**和开发清单的联动**：开发清单页头显示开发冻结的倒计时（“距开发冻结 12 天”；计划日期已过而未达成为“开发冻结已过 N 天”，有实际日期为“开发已冻结”）与“N 项开发计划晚于冻结”；这些开发项的开发阶段计划完成日期单元格标黄。

### 1.4 团队与干系人

**我方关键岗位**（`project` 上的 5 个负责人字段，取项目成员）：项目经理、项目总监 / 交付负责人、方案架构师、开发组长、Basis 负责人。

**模块负责人**（`project_module_lead`）：每个实施模块一位负责顾问。

**客户方联系人**（`project_contact`）：客户方人员不是平台用户，以通讯录方式登记：姓名、职务、部门、角色（甲方项目经理、IT 负责人、业务负责人、关键用户、其他）、负责模块、电话、邮箱、备注。联系方式属于个人信息，只对有 `project.contact:view` 的成员显示。

### 1.5 规模与商务

商务字段敏感，单独授权（`project.commercial:view` / `:edit`）。

| 字段         | 说明                                        |
| ------------ | ------------------------------------------- |
| 合同编号     | 文本                                        |
| 合同模式     | 固定总价、人天计价、按实际工时              |
| 合同人天     | 总人天，一位小数                            |
| 开发人天预算 | RICEFW 开发部分的人天，一位小数             |
| 已计划人天   | 自动汇总：开发清单 FSD 与开发阶段的人天预估 |
| 计划团队规模 | 人数                                        |

“已计划人天 / 开发人天预算”显示为进度条，超出预算标红。

### 1.6 项目健康度

项目经理每周更新一次，作为项目列表与项目首页的核心信号：

- 四个维度：进度、范围、成本、质量，各取 绿 / 黄 / 红；综合状态由项目经理判定（不自动取最差值，红黄的含义需要人来解释）。
- 每次更新记录日期、更新人、一句话说明，形成历史（`project_health`），可以回看趋势。
- 超过 14 天未更新时提示“健康度已过期”。

### 1.7 项目扩展字段（规划中）

企业管理员定义项目扩展字段（参照 Plain 的 Tenant fields 与开发清单自定义列），取值存项目上。菜单已列出，页面为“规划中”。

### 1.8 存储

- 主表 `project` 增加 1.1、1.2、1.4（关键岗位）、1.5 的字段；阶段、里程碑、模块负责人、联系人、健康度历史各为子表，沿用 `(organization_id, project_id)` 复合外键与 `row_version` 乐观锁。
- 状态新增 `live`（已上线）；类型新增 `upgrade`（系统升级）、`conversion`（S/4HANA 转换）。只新增取值，不改写已有数据。
- 已归档项目只读：所有写接口对归档项目返回 409，项目切换器不显示。

## 2. 权限体系

### 2.1 概念

```text
用户 ──任职──> 职位 ──带出──> 默认角色（分配时使用）
  │
  ├──企业级分配──> 角色 + 项目范围（全部 / 指定客户 / 指定项目 / 不含项目）+ 有效期
  │
  └──项目成员 ──> 项目内角色 + 模块范围 + 仅本人负责 + 有效期
                       │
单一角色 = 一组权限点     复合角色 = 一组单一角色（只嵌套一层）
权限点 = 资源:动作（按菜单分组，分为菜单、操作、字段三类）
```

| 概念     | 通行做法中的对应                | 说明                                                                                                   |
| -------- | ------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 权限点   | Permission（`resource:action`） | 程序检查的最小单位，如 `delivery.item:edit`。由代码登记（`packages/contracts/access`），管理员不能新增 |
| 单一角色 | Role                            | 一组权限点                                                                                             |
| 复合角色 | Composite role / 角色继承       | 一组单一角色，只嵌套一层，用于对应实际岗位（同 Keycloak 的 composite role）                            |
| 角色层级 | Role 与 ClusterRole             | 企业级角色可含任何权限点，在企业级分配；项目级角色只含项目级权限点，在项目内分配                       |
| 职位     | 用户组 / 岗位模板               | 用户在实施方的岗位，带一组默认角色；不直接产生权限                                                     |
| 分配     | Role binding                    | 用户 × 角色 × 范围 × 有效期，是唯一产生权限的东西                                                      |
| 数据范围 | 资源范围的绑定 + 属性条件       | 企业级分配指定项目范围；项目内分配可限定模块、限定“仅本人负责”                                         |
| 菜单权限 | 由页面所需的查看权限推出        | 不单独授予，避免“看得到菜单、点进去 403”                                                               |

### 2.2 权限点

命名 `资源:动作`。动作统一为：`view` 查看、`create` 创建、`edit` 修改、`delete` 删除、`import` 导入、`export` 导出、`run` 使用、`finalize` 定稿、`manage` 管理（含增删改）、`read`（读取 SAP）。

权限点按菜单分组，在角色编辑器里以一棵树展示：分组（对应菜单）→ 权限点；每个权限点标出类型：

| 类型 | 作用                             | 例                        |
| ---- | -------------------------------- | ------------------------- |
| 菜单 | 页面的查看权限，决定菜单是否可见 | `project.sap:view`        |
| 操作 | 决定按钮是否可用、接口是否放行   | `delivery.item:delete`    |
| 字段 | 决定敏感字段是否可见、可改       | `project.commercial:view` |

勾选同组的任一操作或字段权限时，自动勾选该组的查看权限；取消查看权限时，同组其余权限一并取消。

程序升级删除某个权限点时，启动同步从所有角色中移除并写审计；新增权限点自动加入超级管理员。

### 2.3 权限点目录

**项目级**（在某个项目内生效）：

| 分组          | 权限点                                                                                                                                                                                                                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目          | `project:view` 查看项目、`project:edit` 修改基本信息与 SAP 形态、`project.plan:edit` 维护阶段与里程碑、`project.health:edit` 更新健康度、`project.team:edit` 维护关键岗位 / 模块负责人 / 客户联系人、`project.contact:view` 查看客户联系人、`project.commercial:view` / `:edit` 商务字段、`project:archive` 归档 |
| 项目成员      | `project.member:view`、`project.member:manage`（增删成员、分配项目内角色；敏感角色的限制见 2.7）                                                                                                                                                                                                                 |
| 项目 SAP 系统 | `project.sap:view`、`project.sap:manage`（增删改系统、设默认）                                                                                                                                                                                                                                                   |
| 开发清单      | `delivery.item:view` / `:create` / `:edit` / `:delete` / `:import` / `:export`、`delivery.config:manage`（自定义列、标签）                                                                                                                                                                                       |
| 开发概览      | `delivery.overview:view`（菜单，按模块范围与仅本人负责收窄）、`delivery.overview.team:view`（看他人的负载与姓名）；见[开发概览设计](development-overview.md)                                                                                                                                                     |
| 开发排期      | `delivery.load:view`（不按范围过滤）；见[开发排期设计](development-load.md)                                                                                                                                                                                                                                      |
| FSD 设计助手  | `agent.fsd:view` 在开发项抽屉查看功能说明书（成果）、`agent.fsd:run` 进入设计助手（对话、上传、批注）、`agent.fsd:finalize` 定稿                                                                                                                                                                                 |
| ABAP 开发助手 | `agent.dev:view` 在开发项抽屉查看开发方案与代码、`agent.dev:run` 进入开发助手（含代码上传与 SAP 同步）、`agent.dev:finalize`                                                                                                                                                                                     |
| SAP 访问      | `sap.development:read`（读取开发系统）、`sap.test:read`（读取测试系统）、`sap.test_data:create`（在测试系统创建测试数据，平台定位决策第 5 节的例外）                                                                                                                                                             |

**企业级**：

| 分组       | 权限点                                                                                  |
| ---------- | --------------------------------------------------------------------------------------- |
| 企业       | `org.profile:view` / `:edit`、`org.security:manage`（SAP 凭据保存策略、强制清除凭据）   |
| 客户与项目 | `customer:view` / `:manage`、`project.directory:view`（全部项目一览）、`project:create` |
| 用户与职位 | `user:view` / `:manage`（建账号、修改、停用）、`user.password:reset`、`position:manage` |
| 角色与权限 | `role:view`（含权限报表）、`role:manage`、`assignment:manage`（企业级分配）             |
| 智能体     | `model:view` / `:manage`                                                                |
| SAP        | `sap.directory:view`（全企业 SAP 系统一览）                                             |
| 审计与运维 | `audit:view`、`audit:comment`、`ops.diagnostics:run`（SAP 连接诊断）                    |
| 开发管理   | `delivery.portfolio:view`（跨项目的项目组合）                                           |

企业级分配带**项目范围**（全部项目 / 指定客户的项目 / 指定项目 / 不含项目）。角色中的项目级权限点在该范围内的每个项目生效，用于交付总监、PMO、项目管理员这类跨项目岗位，不必把他们加进每个项目。

### 2.4 数据权限

逐层收窄：

1. **项目范围**：用户能进入哪些项目 = 有 `project:view` 的项目，来源是项目成员身份或企业级分配的项目范围。项目列表、项目切换器都按此过滤；范围外的项目，接口一律返回 404（不暴露存在）。
2. **模块范围**：项目内分配可限定模块（如只限 FI、CO）。限定后，开发清单中其他模块的开发项**可看不可改**（顾问需要了解全貌，但只能改自己模块的）。模块范围约束开发项的新建（含复制，只能建在本人范围内的模块）、修改、删除和助手使用；不限定即全部模块。改模块只看原模块：能改这条开发项的人就能把它转到别的模块（填错模块时由原模块负责人转出），转出后即按新模块判断，别的模块不能把它转进来（2026-10-18，backlog BUG-004）。
3. **本人范围**：项目内分配可勾选“仅本人负责”。勾选后，只能修改自己负责的开发项（任一阶段负责人或创建人）、只能在自己负责的阶段使用助手（设计看 FSD 阶段负责人，开发看开发阶段负责人）。用于分包开发人员。

同一权限点来自多个分配时取最宽：任一分配不限模块即全部模块，任一分配不限本人即不限。字段权限（商务、联系人）在此之上单独控制。

### 2.5 预置角色

预置角色标“系统”，不可修改、不可删除，可以“复制为新角色”后调整（同 Plain 的 Owner / Admin）。超级管理员的权限点随目录自动更新。

**企业级单一角色**：

| 编码                | 名称         | 权限点                                                                                                                                                                                                                                                                                                        |
| ------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SYS_SUPER_ADMIN`   | 超级管理员   | 全部；企业至少保留一名有效的超级管理员                                                                                                                                                                                                                                                                        |

职位是用户在实施方的岗位，用来**带出默认角色**，减少逐个分配。预置以下职位（企业数据，可改、可增删）：

| 业务顾问   | —                                 | `C_FUNC`                   |
| 开发组长   | —                                 | `C_DEV_LEAD`               |

- 用户有一个主职位，另记“擅长模块”（多选）。加入项目时，默认角色取职位的项目内角色，默认模块范围取擅长模块与项目实施模块的交集（可修改）。

- 用户有“人员类型”：员工、分包、外部（为将来的客户用户预留，暂不开放）。分包与外部人员（非员工）的任何分配都必须设结束日期。

### 2.7 授权规则

- **有效权限** = 未过期的企业级分配（项目级权限点限于其项目范围）∪ 该项目内未过期的分配，取并集后按模块范围、本人范围收窄（2.4）。每次请求实时计算，变更立即生效。
- **不能越权授予**：
  - 企业级分配、编辑角色：操作人必须持有角色中的每个权限点（企业级权限点在企业级持有；项目级权限点通过“全部项目”范围的企业级分配持有）。
  - 项目内分配：持有 `project.member:manage` 即可分配项目级角色；但角色中含**敏感权限点**（`project.member:manage`、`project.commercial:view`、`project.commercial:edit`、`project:archive`）时，操作人必须在本项目持有这些权限点。
  - 任何人都不能修改自己的分配（增加、延长或删除）。
- **超级管理员保护**：不能删除、到期或停用最后一名有效的超级管理员。
- **有效期**：开始与结束日期（含当天）；结束日期在 7 天内的分配在列表中标“即将到期”。
- **离场**：停用用户或移出项目时，立即撤销其登录会话（停用）或项目内分配（移出），并删除该用户在相关项目 SAP 系统上保存的凭据（3.4）。

### 2.8 可解释与报表

- **用户权限视图**：某用户的企业级权限，以及在每个项目的有效权限点，每项注明来自哪个角色、哪次分配、有效期至何时。
- **权限反查**：某个权限点在全企业由哪些人通过哪些角色持有。
- **角色使用情况**：每个角色被分配给了哪些人、在哪些项目。
- **无权限说明**：接口返回 403 时附带缺少的权限点编码与名称；页面显示“需要‘开发清单管理’中的‘删除开发项’权限”，而不是一句“无权限”。
- **审计**：角色的增删改、分配与撤销、职位默认角色变更全部写入审计日志。
- **以他人视角预览**（规划中）：管理员以只读方式查看某用户看到的菜单与按钮。

## 3. 项目 SAP 系统与个人凭据

### 3.1 原状与问题

- SAP 系统登记在企业级（`sap_system`，含所属客户与对客户的临时授权 `sap_system_grant`），项目按 DEV / QAS / PRD 三个固定环境各选一个系统（`project_sap_config`），每个环境只能一个。
- 项目级配置可以保存共享的 SAP 用户与密码，个人配置可覆盖（`user_project_sap_config`）；测试系统的个人用户和密码只存在 API 进程内存。
- 问题：一个项目常有多套开发 / 测试系统（S/4 与 BW、主系统与沙箱、多个 Client）；共享账号在 SAP 审计中追溯不到人；平台定位决策已确定不连 PRD。

### 3.2 项目 SAP 系统

每个项目维护自己的 SAP 系统清单（`project_sap_system`）：

| 字段         | 说明                                       |
| ------------ | ------------------------------------------ |
| 名称         | 如“S/4 开发 100”，在助手与开发清单中显示   |
| 用途         | 开发系统、测试系统（不允许生产系统）       |
| 系统标识 SID | 3 位字母数字，如 `S4D`                     |
| ADT 地址     | `https://host:port`，助手经 ADT 访问       |
| Client       | 3 位数字，必填                             |
| 登录语言     | 默认取项目主语言                           |
| 说明         | 如“FI 沙箱，数据每周刷新”                  |
| 默认         | 每种用途最多一个默认系统                   |
| 状态         | 启用、停用；停用后助手不可选，历史记录保留 |
| 最近连接测试 | 结果、时间、后端版本（由连接测试写入）     |

**不保存任何用户名和密码。**同一 SID 的不同 Client 是不同的记录；同一项目内“用途 + ADT 地址 + Client”唯一（小型项目可能用同一个 Client 兼做开发与测试）。

- **默认系统**：设计助手默认使用默认测试系统，开发助手默认使用开发项的目标系统或默认开发系统，测试数据使用默认测试系统。
- **开发项目标系统**：开发项可选“目标开发系统”（默认取项目默认开发系统），用于一个项目同时开发 S/4 与 BW 对象的情况。
- **按消息切换**：助手的输入框可在项目已启用的系统间切换（契约 1.12 的“DEV / QAS”改为具体系统）；运行记录保存实际使用的系统与 Client。
- **复制**：可从同一客户的其他项目复制系统清单。
- **全企业一览**：`sap.directory:view` 可只读查看各项目登记的系统，便于 Basis 了解全局；不再单独维护企业级系统。

### 3.3 个人凭据

各系统的 SAP 用户与密码由用户本人输入。首次在助手中使用某系统、或在“我的 SAP 凭据”中登录时，填写 SAP 用户、密码、保存方式；平台先用它登录一次 SAP 验证，成功后才保存。

| 保存方式     | 存放位置     | 有效期                                                | 适用                     |
| ------------ | ------------ | ----------------------------------------------------- | ------------------------ |
| 本次登录有效 | API 进程内存 | 平台退出登录、会话过期（最长 8 小时）或服务重启时失效 | 公用电脑、高敏系统       |
| 加密保存     | 数据库，加密 | 企业安全策略规定的天数（默认 30 天）                  | 日常频繁使用（默认选项） |

“加密保存”只在企业安全策略允许时出现（3.4）。

### 3.4 安全策略

**加密**

- AES-256-GCM 加密，每条记录随机 IV；主密钥来自部署环境（`SAP_CREDENTIAL_KEY`），数据库中只有密文，并记录密钥版本号（为轮换预留）。
- 附加认证数据绑定 `用户 + 项目 SAP 系统 + ADT 地址 + Client + SAP 用户`：密文复制到别的行无法解密；系统地址或 Client 被修改后，旧凭据自动失效并删除。

**使用**

- 只用于本人发起的请求（本人的助手运行、本人的连接测试、本人授权的测试数据）。管理员、项目经理都不能使用他人的凭据。
- 接口从不返回密码或密文，只返回“SAP 用户 · 保存方式 · 保存于 · 到期于 · 最近成功使用”。
- 日志、错误信息、审计、模型上下文中都不出现密码。

**SAP 侧的特殊情况**

- **防止锁定 SAP 用户**：SAP 默认连续 3～5 次密码错误就锁定用户。已保存的凭据一旦登录被拒，立即作废并删除，提示用户重新输入；平台不自动重试。
- **密码过期、用户锁定**：连接失败的原因原样显示（如“密码已过期”“用户已锁定”），提示用户在 SAP GUI 中处理或联系 Basis；平台不代改 SAP 密码。

**撤销**

- 用户可在“我的 SAP 凭据”中查看与删除自己的全部凭据。
- 用户被停用、移出项目，或系统被删除 / 停用、地址或 Client 被修改时，相关凭据立即删除。
- 有 `org.security:manage` 的管理员可按用户强制清除（不查看内容），用于离职与安全事件。

**企业安全策略**（`sap_credential_policy`，`org.security:manage`）

| 策略                  | 默认              |
| --------------------- | ----------------- |
| 允许加密保存 SAP 密码 | 允许              |
| 加密保存的最长天数    | 30 天             |
| 闲置自动失效          | 14 天未使用即失效 |
| 分包人员允许加密保存  | 不允许            |

**审计**：凭据的保存、登录被拒作废、删除、强制清除写入审计日志（不含内容）；成功使用只更新“最近成功使用”时间。

### 3.5 本地开发

本地开发的凭据文件（`SAP_MCP_PROFILE_FILE`，契约 3.4）保留，仅非生产环境有效：项目系统的 ADT 地址与 Client 与文件一致时，可一键用文件中的凭据登录（保存方式为“本次登录有效”），便于自动化测试。

### 3.6 迁移

| 原有                                       | 处理                                                                                        |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `project_sap_config` 的 DEV / QAS          | 对应的企业级系统与 Client、语言复制为该项目的 `project_sap_system`（开发 / 测试），设为默认 |
| `project_sap_config` 的 PRD                | 不迁移                                                                                      |
| 项目级共享 SAP 用户与密码                  | 不迁移，随表删除（用户 2026-10-17 确认）                                                    |
| `user_project_sap_config` 的个人用户与密码 | 不迁移，随表删除；用户首次使用时重新输入                                                    |
| `sap_system`、`sap_system_grant`           | 删除                                                                                        |
| `sap_test_data_run.system_id`              | 外键删除，历史值保留；新记录写项目 SAP 系统的标识                                           |

- **详情页**：2026-10-29 起设置区的记录不再另开详情页，改在列表的抽屉里查看与修改（用户、角色原详情页删除）；项目的各设置页（基本信息、计划与健康等）仍是卡片页：按卡片分组，每张卡片底部右下角“保存”，只保存本卡片。
- **角色编辑**：权限点树（分组 → 权限点，带类型标签与说明，可搜索）；复合角色编辑为单一角色的勾选列表，实时显示合并后的权限点数。
- **成员与权限**：概要一行为成员数、项目经理、限定模块与即将到期人数；筛选下拉为“全部成员 / 即将到期 / 分包与外部”。表格列为成员（头像、姓名，下一行职位 · 账号 · 人员类型）、项目内角色标签、范围（模块 · 仅本人负责）、有效期（即将到期显示黄色标签）、排序码（开发排期中的人员顺序，0–9999 可留空，持“管理成员”者在行内直接修改，含自己）与操作（编辑、⋯ 里的“移出项目”）；自己那一行不能编辑角色与范围、不能移出。添加与调整在右侧抽屉里：先选成员（添加时），再选角色（卡片，附一句说明，同 Plain），最后是模块范围、仅本人负责与有效期。条件不全时点“保存”，抽屉内说明缺什么：未选成员、企业内没有可添加的用户（先到“设置 → 企业 → 用户”新建）、未选角色、分包与外部人员未填截止日期。
- **SAP 系统**：概要一行为默认开发系统与默认测试系统；筛选下拉为“全部用途 / 开发系统 / 测试系统”，工具行右侧为“从其他项目复制”与“登记系统”。表格列为默认（星标，每种用途一个）、系统（名称，下一行 SID · Client · 语言）、用途（下一行 ADT 地址）、我的登录、最近测试与操作（编辑、登录 / 退出、测试、⋯ 里的“设为默认”“删除”）。登记与编辑在右侧抽屉里，分“基本信息”“接入配置”两组；登录 SAP 与从其他项目复制仍是对话框。
- **用户权限视图**：用户抽屉的“有效权限”分组，按项目分组展示权限点及来源。

## 5. 接口与实施要点

- **权限内核**：`apps/api/src/modules/access`，公开入口 `public.mjs`：`createAccess(pool, organizationId)` 提供 `organization`、`project`、`projects`、`requireOrganization`、`requireProject` 等方法；`syncBuiltInRoles(db, organizationId)` 在应用启动与初始化时同步预置角色与职位。各模块只通过它判断权限，不直接查角色表。
- **会话接口**返回当前用户的企业级权限点；`GET /api/projects/:id/access` 返回该项目的有效权限点（含模块范围），前端据此渲染菜单与按钮。
- **一致性**：授权写操作在企业级咨询锁内执行，并检查 `row_version` 乐观锁与“最后一名超级管理员”。
- **测试**：每个写接口在缺少对应权限点时返回 403、在范围外项目返回 404，均有集成测试覆盖。
