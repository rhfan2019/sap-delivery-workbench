# 审计日志与优化建议

状态：已实现（2026-10-12）。页面：后台管理 → 审计日志（`/workspace/audit`），仅企业管理员可见。归属见[目录与依赖契约](../architecture/repository-contract.md) 3.2 节。

页面基于另一会话开发的“智能助手日志”页面（未提交、准备阶段被删除，从其编辑历史恢复）改造，保留布局与交互，按 abap-fsd-agent 的新数据重写接口与详情内容。

## 页面

| 标签     | 内容                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 助手运行 | 每一轮运行一行：时间、开发项、用户、模型、状态、结束原因、耗时、模型/工具调用、工具失败、Token、评论数；按时间、状态、模型、项目、开发项、关键词筛选 |
| 统计分析 | 失败率、提问率、平均耗时、工具失败率、Token；结束原因分布；按工具、按模型统计；按天趋势                                                              |
| 操作审计 | `app.audit_event`：时间、操作人、操作、结果、对象、详情                                                                                              |
| 优化建议 | Claude Code 发布的建议方案列表与正文                                                                                                                 |

单轮详情（`/workspace/audit/runs/:id`）：结论（状态、结束原因、错误）、评论、本轮对话（用户输入、助手回复、提出的问题）、产出文档（版本、改动章节、未声明修改）、工具调用时间线（参数与结果、两次调用之间的模型思考间隔，超过 30 秒、120 秒分级提示）。会话趋势（`/workspace/audit/sessions/:id`）：同一会话逐轮耗时、Token、工具调用及增长提示。

## 口径

- 状态：`completed` 且结束原因为 `asked` 记为“已提问”；其余为轮次状态（已完成、失败、已停止、已中断、运行中）。失败率 =（失败 + 中断）/ 全部轮次。
- 模型思考间隔：本次工具调用开始时间与上一次调用结束（或轮次开始）之间的时间，近似模型生成下一步的耗时。
- 工具调用结果保存前 2,000 字符（2026-10-12 起；此前为 160 字符摘要）。

## 优化建议流程（按需，手动触发）

1. 测试中在每一轮运行详情页写评论。
2. 用户让 Claude Code “分析审计日志”。
3. Claude Code 导出日志与评论：`npm run audit:export -- --since 2026-10-11`，输出到 `.runtime/artifacts/assistant-logs/`（JSON 含每次工具调用，Markdown 为可读摘要）。
4. Claude Code 结合导出材料与代码写出建议方案（Markdown），发布到页面：`npm run audit:publish -- proposal.md --title "标题" --since 2026-10-11 --source <导出的 JSON>`。

平台本身不调用模型生成建议，也没有定时任务。

## 权限与安全

- 接口 `/api/audit/*` 均要求企业管理员。评论只能删除自己的（软删除，记录保留）。
- 运行时数据库账号对 `app.audit_event` 由“只写”调整为“读 + 写”，仍不能修改或删除（`provision.mjs`，并由 `tests/integration/database/runtime.test.mjs` 断言）。
