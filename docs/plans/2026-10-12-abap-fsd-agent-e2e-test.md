## 1. 目标与范围

在真实环境（组织当前的默认模型，每轮开始前从大模型配置读取并记录名称，用户可能随时调整；项目 VIRTUAL 的 DEV SAP 系统，只读 MCP）上，把 FSD 设计助手当前支持的功能完整走一遍：

需求 → 澄清提问 → 回答 → 出稿 → 追问 → 批注修订 → 对话修改 → 附件补充需求 → 中途停止 → 刷新续流 → 定稿标签与导出 → 审计日志复核。只执行 DEV-0031 主流程（T1～T11）；副本对照（T12）因缺乏正确样本暂不执行。

不在范围：FSD 内容质量评分（只记录，不判失败）；权限与多用户；性能压测；步骤上限、服务繁忙重试（无法稳定触发，已有自动化测试覆盖）。

## 3. 执行方式

- **界面操作走内置浏览器**（以 `.env` 的测试管理员登录）：发送消息、回答问题卡、选中原文加批注、上传附件、停止、刷新、打标签、导出。这样同时验证前端。
- **核对走接口和数据库只读查询**：会话详情、轮次状态、工具调用、文档版本与差异、审计接口。
- 每一轮结束后截图核对（截图仅用于当场核对，未存档）并记录指标：耗时、模型调用 / 工具调用（失败数）、输入 / 输出 Token、提问数、文档版本与长度、`check_document` 结果、未声明修改。
- 每一轮在审计日志详情页写一条评论（我的观察），T11 时用于生成优化建议。
- 出现阻断性问题（服务报错、页面白屏、轮次卡死超过 10 分钟）立即停下向你报告，不自行改代码；非阻断问题记录后继续。

本节保存各问题的原始分析与修改方案；现状与优先级以[待办与问题清单](backlog.md)为准（2026-10-28 核对：E2E-06c 并入 FEAT-002，E2E-06e 已修复，其余仍待处理），交接文档、重构计划只引用编号。

### E2E-01 系统指令承诺了未实现的导出内容（高，需决定）

- **现象**：T8 中助手拒绝把字段核实结果写入附录 C，理由是“导出时程序会自动生成 SAP 核实记录”；T9 导出 `DEV-0031-FSD-v4.md` 只有正文。
- **证据**：轮次 `1b4fe099-9926-4637-9c68-2863796398c8` 的回复；导出内容与第 4 版正文一致（6,569 字符）。
- **根因**：`apps/api/src/modules/abap-fsd-agent/prompts/system.md` 第 208 行写“封面、文档变更记录和 SAP 核实记录由程序生成，你不要写”，第 346 行把“程序生成的 SAP 核实记录”列为证据链的一部分；而导出接口 `routes.mjs` 第 274～285 行只返回 `doc.markdown`。重构计划 4.6 节也只计划“导出 Markdown”，三项从未进入实施范围。提示词与实现脱节。
- **设计依据**：方向决策 5.3 节“FSD 中的事实区分已核实和推断；查询记录即证据链”。
- **修改方案**：
  - **方案 A（推荐，与 5.3 节一致）**：导出时由程序附加三部分——封面（项目、开发项、版本、定稿标签、模型）；文档变更记录（取各版本的轮次时间、改动章节与修改声明）；SAP 核实记录（取本会话成功的 SAP 工具调用：对象、查询语句或表名、时间、轮次）。界面文档面板同步提供预览。
  - **方案 B**：删除 `system.md` 第 208、346 行的承诺，改为要求模型在附录中写明关键核实依据。改动小，但证据链靠模型自述，不可靠。
- **涉及**：`routes.mjs`（export）、`repository.mjs`、`prompts/system.md`、重构计划 4.6 节。

### E2E-02 没有版本差异对比视图（中）

- **现象**：T9 只能切换版本、看“本版改动章节”列表，无法看到两个版本之间改了什么文字。
- **根因**：`DocumentPanel.vue` 只有版本下拉、改动章节列表与未声明修改提示；`GET /sessions/:id/documents/:version` 返回该版本全文与章节级比对结果（`repository.getDocument`：`markdown`、`changes`、`comparison`、`labels`），没有文本差异。重构计划阶段 C 第 3 项要求的“版本差异”未实现。
- **修改方案**：前端实现，不改后端：取所选版本与上一版的全文，按章节拆分（与后端 `document.mjs` 的 `splitSections` 规则一致），对改动章节显示逐行差异。顺带修正“第 1 版显示全部章节为改动”（第 1 版无上一版，显示“首版”）。
- **涉及**：`apps/web/src/features/abap-fsd-agent/DocumentPanel.vue`、前端单元测试。

### E2E-03 `reply_comment` 被用于回复普通聊天（中）

- **现象**：T7 首次请求（无批注）中，助手先调用 `reply_comment` 回复用户，失败“批注编号不存在”，再改用文字回复。
- **证据**：轮次 `ca8a1647-f9d5-40cd-86e8-29c9699e9617`，审计统计中唯一一次工具失败。
- **根因**：工具说明（`tools/workspace.mjs` 第 81 行）只写“回复用户的一条批注”，未说明批注编号必须来自未解决批注列表、普通对话应直接用文字回复。服务端已校验（第 168 行），无数据错误，只浪费一次往返。
- **修改方案**：工具说明改为“仅用于回复未解决批注；comment_id 必须取自本轮提供的批注列表；普通对话直接用文字回复”。可选：本轮没有未解决批注时不向模型提供该工具。
- **涉及**：`tools/workspace.mjs`、`loop.mjs`（可选项）、单元测试。

### E2E-04 首稿偏薄、口径疑点未列入未决（低，只记录不计分）

- **现象**：T2 第 1 版 5,460 字符，附录 A 写“暂无”；已交数量直接汇总 `LIPS-LFIMG`，未区分是否已发货过账、未做单位换算；T3 中助手解释了“按过账还是按创建交货单”两种口径，但没有建议登记附录 A（后经 T4 批注才改）。
- **根因**：模型行为与系统指令要求的落实程度，与本轮模型（Gemini）相关，需在多模型批量测试中对比后再定。
- **修改方案**：暂不改。批量测试中按模型统计首稿长度、附录 A 条目数；若普遍存在，在系统指令中加强“有多种口径且客户未确认的，必须登记附录 A”。
- **涉及**：`prompts/system.md`（视批量测试结果）。

### E2E-05 重复读表与串行查询（低）

- **现象**：T1 先用 `ddicElement` 一次读取 VBAK/VBAP/VBEP，随后又单独读取 VBAP、VBEP；T2 的 13 次 `runQuery`（DD03L/DD04T/DD07T）逐个串行，每次间隔约 5～15 秒模型时间。
- **根因**：`loop.mjs` 第 185～187 行的重复检测只拦截“同一工具、同一参数”第 3 次及以后的调用，参数不同的重读不会被拦；`loop.mjs` 中的表结构缓存（`tableCache`）只服务写入后的自动校验，不覆盖模型主动调用的 `ddicElement`；系统指令虽要求并行和批量，模型未遵守。
- **修改方案**：在 SAP 工具层按“系统 + 客户端 + 表名”缓存 `ddicElement` 结果（数组参数拆开逐表命中），命中时直接返回并注明“本会话已读取”；系统指令补充“同类字典查询用 IN 列表合并为一次”。
- **涉及**：`tools/sap.mjs`、`loop.mjs`、`prompts/system.md`、单元测试。
