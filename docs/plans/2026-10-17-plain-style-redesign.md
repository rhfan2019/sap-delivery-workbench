# 参照 Plain 重写前端界面层：计划

日期：2026-10-17 · 状态：用户 2026-10-17 确认，按批次执行

用户 2026-10-17 决定：本网站最初由 vibe coding 生成，界面不再修补，而是参照 Plain（app.plain.com）的导航、菜单、页面布局与设计语言**重写前端界面层**；只保留一套 Plain 风格外观，下线 Airbnb、Airtable 主题并取消主题换肤；开发清单表格改用 TanStack Table（用户要求其满足复杂筛选、排序、动态显示列与保存布局，核实后满足，见第 3 节）。

本文第 1 节记录在 Plain 里实测到的设计语言（用户登录后由 Claude 只读浏览，未修改任何数据），第 2 节起为重写的边界、决定与批次。规范见 [DESIGN.md 2.0](../specs/DESIGN.md)，契约见 1.15。

## 1. Plain 的设计语言（实测）

### 1.1 布局：一层底、几块浮起的白板

- 页面底色 `#F9F9FC`；内容放在白色圆角面板里（圆角 12px），面板四周留 8px 缝，边缘是 1px 半透明描边 `rgba(32,39,44,.08)` 加极淡投影。整页像几块纸放在桌上，而不是一张被线切开的表格。
- 左侧导航分两层，总宽 345px：
  - **图标栏** 56px：32×32 图标按钮，圆角 6px，选中为浅灰底 `#E7E7EF`；悬停出深色小提示（12px 浅字）。上面放模块（Support、Sidekick、Workflows、Insights、Settings…），底部放通知、帮助、头像。
  - **二级菜单** 289px：顶部是工作区切换器、搜索、新建；下面是当前模块的菜单，项高 32px、圆角 6px、左图标右计数；未选中文字为次要色 `#636370`，选中为浅灰底、正文色、字重 550。分组标题（Browse、Admin、Workspace…）可折叠。
- 打开一条记录时（对话详情）不弹抽屉，而是**列表收窄成一块 400px 的面板，详情占右侧一块大面板**，二级菜单收起，只留图标栏。
- 没有顶部导航栏：页面标题、主按钮都在内容面板内部。

### 1.2 颜色：灰阶 + 六种色相，各有固定角色

Plain 的颜色不是“品牌色 + 状态色”，而是 6 个色相（neutral、blue、green、purple、red、yellow），每个色相都有同一套角色：

| 角色           | 用途               | 例（blue）                        |
| -------------- | ------------------ | --------------------------------- |
| background-1/2 | 整块浅底           | `#FDFDFF` / `#F7F9FF`             |
| fill-1/2/3     | 标签、色带、按钮底 | `#EEF2FF` / `#E1E8FF` / `#D3DDFF` |
| border-1/2/3   | 描边               | `#E1E8FF` / `#D3DDFF` / `#ADBCFF` |
| text-1/2       | 深色字 / 强调字    | `#232964` / `#4A52D1`             |
| icon-1/2       | 图标               | `#448BFF` / `#7DAEFF`             |
| solid-1/2      | 实心按钮、徽标     | `#5C67F4` / `#525CDB`             |

中性色：正文 `#1F1F28`，次要 `#636370`，图标 `#8E8E9C`，描边 `#E7E7EF` / `#E0E0E9` / `#CDCDDB`，填充 `#F0F0F5` / `#E7E7EF`。

**用法是语义化的**：

- 奶黄（yellow fill `#FFFAE9`）= 内部备注、测试数据；
- 淡紫蓝（blue fill `#EEF2FF`）= 状态事件（“等待首次回复”）；
- 薄荷绿（green fill `#E2F9E8`，字 `#074022`）= AI 的建议动作；
- 浅灰（`#F9F9FC`）= 客户消息；
- 品牌绿 `#1BD379` 只出现在 logo 与 AI 图标上。
- 主按钮是**墨色** `#1F1F28` 白字，不是品牌色。

### 1.3 字体与字号

- 正文 Inter 14/20，字重只用 400 / 475 / 550（可变字体的中间字重，比 500/600 更细腻）。
- 页面标题用 Whyte（商业字体）20–24px、字重 400——标题不加粗，靠字号和字体性格。
- 小字 12/16；表头 12/16、字重 550、次要色；键盘提示 11px、字重 550、带 1px 描边的小方块。
- 等宽 geistMono。

### 1.4 圆角、阴影、间距

- 圆角：2 / 4 / 6 / 8，面板 12，弹层 10。按钮、菜单项、输入框 6；标签 4；消息块 8。
- 阴影只有三档：卡片 `0 0 0 1px #20272c14, 0 1px 1px #20272c14`；弹层 `0 1px 2px #20272c3d, 0 2px 6px 2px #20272c14, 0 2px 8px #20272c14`；对话框更深一层。
- 控件高度：按钮 34px，菜单项 32px，下拉菜单项 30px，输入框 32px，页签 28px。

### 1.5 组件

- **列表页**（Workflows）：面板内左上图标 + 24px 标题，右上一个墨色主按钮（带图标、34px、小投影）；页签是纯文字、选中加浅灰底；搜索框占满一行；右侧“Filters F”。表格没有竖线，表头小号灰字，行名 14/550，状态与类型用淡色小标签，“创建人”显示为“头像 + 名字 · 时间”，行尾 ⋯。
- **对话详情**：
  - 顶栏：头像、类别标签、编号与标题、时间，右侧是视图切换和面板开关。
  - 时间线：“Today”日期分隔；系统事件只占一行灰字，里面可嵌小标签；消息是圆角 8px 的色块，头像放在块外。
  - 状态事件是一条淡紫蓝色带；AI 摘要配一个薄荷绿按钮“Draft a … reply”。
  - **底部浮动操作条**：“Reply R · Note N · More | Sidekick B”，白底、圆角 12、细描边、柔和投影；点 Reply 后，输入框从操作条上方展开（带“esc ×”），聚焦时是 2px 蓝色描边。
  - 右侧属性面板：“标签 / 值”每行 40px，分组可折叠；没有内容时显示空状态（图标方块 + 标题 + 两行说明 + 小按钮）。
- **下拉菜单**：白底、圆角 10、弹层阴影；每项左边一个小彩色图标，接着是文字和灰色说明，最右边是快捷键。
- **设置页**：二级菜单顶部有搜索，菜单按 Admin / Workspace / Data model 分组；内容区居中一栏，每个分组有标题和说明，下面是两列卡片（图标方块 + 标题 + 一句说明），分组之间用细线分隔。
- **引导卡**：二级菜单底部的“Next steps”卡片，带进度条。

### 1.6 动效：克制而一致

- 时长只有三档：**75ms**（悬停换色）、**150ms**（多数过渡、弹层）、**300ms**（较大的变化），都用 ease-in-out。
- 弹层出现：朝弹出方向位移 4px 加淡入，150ms。对话框：从下方 16px、缩放 0.96 淡入。折叠分组：动画高度变化。侧滑面板：`transform 0.4s cubic-bezier(0.32,0.72,0,1)`。加载时用骨架屏的流光效果。
- 没有弹跳、上浮、发光。精致感来自**每个可交互元素都有一致、短促的反馈**，不是来自动画本身。

> 结论：Plain 好看靠的是“结构 + 克制 + 一致”，而不是颜色或特效。这也解释了前两轮原型为什么不行——它们没改结构，只加了颜色和动效。

## 2. 重写的边界

| 保留（不改）                                                                                  | 重写                                                            |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 后端 `apps/api`、数据库与接口                                                                 | 全部页面模板与样式（`main.css`、各 feature 的 css、页面样式块） |
| 共享契约 `packages/contracts`                                                                 | 外壳：侧边栏、顶栏、布局                                        |
| 前端数据与逻辑层：`services/`、`useAgentSession` 等组合函数、`model.ts`、路由守卫、流事件协议 | DESIGN.md、令牌；主题包与换肤（下线）                           |
| 接口与单元测试                                                                                | 依赖页面结构的 e2e 断言（随页面一起改）                         |

用户 2026-10-17 要求：只借鉴 Plain 的展示风格，设计 / 开发助手的流式反馈与全部功能（运行步骤、实时状态、待决定问题、停止与继续、草稿与成果面板、附件、批注加入对话等）必须完整保留，第 4 批只改外观与排布。

做法：每页**重写模板、复用逻辑层**；新页面上线时删除该页旧样式与旧组件，不保留两套。批次之间网站始终可用，每批检查通过后提交推送 main。

不复制 Plain 的标志、品牌绿、商业字体（Whyte、ABC Favorit）与文案；只借鉴布局、配色体系、组件形态与动效节奏。

## 3. 技术决定

- **组件底座**：用已安装的 reka-ui（无样式交互组件）编写自有组件；`components/ui` 的 shadcn 风格组件逐步替换。
- **表格**：开发清单改用 `@tanstack/vue-table` 8.x（第 3 批采用 8.21.3：9.x 为 2026 年的新大版本、API 改为按需引入特性，8.x 是成熟稳定版）。它提供排序（含多列）、全局与按列筛选（可自定义筛选函数）、列显示 / 顺序 / 宽度 / 固定、行选择，状态为普通对象，可原样保存为布局；它不带界面，列宽拖动手柄、固定列与单元格编辑由我们实现。现有筛选逻辑在清单页内，继续沿用。行数很多时再加 `@tanstack/vue-virtual`。全部迁移后删除 `vxe-table`、`vxe-pc-ui`。
- **主题**：只保留一套外观，深色跟随系统，不提供手动切换。个人设置中的“外观”去掉；`GET/PUT /api/preferences` 与 `app.user_preference` 前端不再使用，接口与表的删除另行确认（涉及公开接口与数据）。
- **动效与快捷键**：按 DESIGN.md 第 7 节和第 5 节的 `kbd`；快捷键用统一的注册机制，输入框内不触发。

## 5. 风险

- **表格**：TanStack Table 不带界面，列宽拖动、固定列、单元格编辑、批量勾选要自己做，是工作量最大的一项。
- **路由**：开发项详情从抽屉变为页面，设计 / 开发助手并入记录页；旧链接需跳转，e2e 需同步修改。
- **顶栏去掉后**，组织与项目信息由二级菜单顶部承担，所在位置由菜单选中项和面板标题表达。

## 6. 执行记录

- **第 4 批（2026-10-17）**：记录页保留两个地址作为“设计 / 开发”两个页签，旧链接无需跳转；开发项信息从标题弹层改为右侧可折叠的属性面板。对话时间线、运行步骤、待决定问题、测试数据授权、附件、批注加入对话与成果面板的组件和流式逻辑（`useAgentSession`、`AgentWorkbench` 的脚本）未改，只换外观与排布。输入框常驻底部为浮动卡片，而不是规范初稿中“操作条点开再展开”的形式：对话是助手页的主要任务，多一步点击得不偿失；改为 R 聚焦、U 上传两个快捷键。
- **第 5 批（2026-10-17）**：新增设置总览 `/workspace/admin`；后台各子页面沿用现有逻辑与组件，统一由全局页头、按钮、页签与提示条的 Plain 样式排版（`main.css` 的公共类改用新令牌），去掉英文眉题；规划中的页面改为空状态。子页面内部样式中的旧变量名在第 7 批统一替换。
- **第 6 批（2026-10-17）**：首页去掉深色横幅、环形装饰与英文眉题，改为页头、常用卡片与“我的项目 / 知识与资产”两栏；我的项目与项目详情改用基础组件（标签、骨架屏、空状态、属性分组）。知识与资产各页仍为“规划中”的空状态。登录页与修改密码页改用新令牌；个人设置中的修改密码不再套整页卡片。首页专用样式移入页面，`main.css` 只留公共类。
