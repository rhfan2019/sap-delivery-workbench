## 1. 现状一句话

开发助手首版已按[方向决策](../architecture/2026-10-13-abap-dev-agent-direction-decision.md)与[实施计划](2026-10-14-abap-dev-agent-implementation.md)实现：开发项工作区“开发”阶段，输入 FSD / 资料 / 口头需求，产出**开发方案 + 一份继承 `YCL_FRH_REPORT` 的完整可执行程序**，支持批注修订、版本差异、上传或从 SAP 同步交回代码；首版只支持开发类型“报表”“功能”。2026-10-14 端到端测试“有条件通过”（[测试记录](2026-10-14-abap-dev-agent-e2e-test.md)）。之后前端随全站按 Plain 重写，输入框可按消息选择 SAP 系统与模型、用 + / @ 引用开发项资料。用户要**先确认功能好用**，token 优化暂缓。

## 2. 下一步：测试重点（建议顺序）

以“开发顾问是否好用”为标准，每个场景记下：模型名、耗时、工具调用、是否提问、代码行数、静态校验结果、人工核对的问题。

1. **有 FSD 的完整流程（00011）**：发“请根据设计助手的 FSD 写开发方案和代码”。看：是否读取 FSD、是否查 SAP 核实、方案与代码是否同轮写出、代码是否符合 `report.md` 与范例（SRI、CTE 计算下推、逐列字段目录、事件块）。
2. **无 FSD 的后续流程（00016 `6e10b4c9`）**：回答 5 个问题（可选推荐），看是否先出方案再写代码、口径是否按答复落实。
3. **批注修订**：对代码行和开发方案各加批注，看是否只改该改之处、是否回复批注、修改声明比对是否有“未声明修改”。程序会拒绝“没改却说改了”的回复。
4. **交回代码**（测试记录第 4 节尚未执行）：
   - 上传文件：把改过的代码存成 `.abap` 或 `.txt` 上传，说明“这是我改过的代码”，看是否先确认再 `import_code`、是否给出差异、之后的修改是否保留手工改动。此前只有集成测试（模拟模型）覆盖。
   - SAP 同步：需先在开发清单为该开发项登记程序对象（`R3TR PROG <名称>`），且 SAP 中有该程序（可用 `YDEMO_FRH_0021` 实验）。读取能力已验证，完整流程未跑。
5. **资料变化**：在设计助手里改 FSD 出新版本后，回到开发对话，看是否标出“新增”资料、是否列出影响、与先前明确决定冲突时是否提问。
6. **功能类开发项**（可编辑 ALV、BAPI 写回；00002、00005、00009 等还没测过）：首版规范对写回只有原则性描述、没有范例，预期弱于报表，重点看锁、提交回滚、逐行结果。
7. **不支持的情况**：接口 / 增强类开发项应告知不支持；变更类型“优化”时应告知只开发新对象。
8. **界面**：版本切换、差异（对比任意早期版本）、依据、导出代码与开发方案、复制代码、定稿标签、批注“原文已变”状态；没有 `agent.dev:run` 的用户只能在开发项抽屉里查看成果。
9. **设计助手回归**：共用组件改动后，确认设计阶段的出题、写稿、批注、版本、导出仍正常。

生成的代码最终要用户粘贴到 SAP 做语法检查和运行；记录用户反馈的语法错误类型，作为系统指令与静态校验的改进输入。
