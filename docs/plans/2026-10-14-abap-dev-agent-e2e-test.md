# abap-dev-agent 端到端测试

> 2026-10-14。依据：[实施计划](2026-10-14-abap-dev-agent-implementation.md)第 7 节、[方向决策](../architecture/2026-10-13-abap-dev-agent-direction-decision.md)第 10 节。环境：本机开发环境，目标系统 SELF-S4H-2020（S4CORE 105 · SAP_BASIS 755，client 100），组织默认模型 Gemini 3.1 Pro Preview。本文是本轮问题的唯一权威清单。

## 1. 结论

**有条件通过。** 开发助手能读取设计助手的定稿 FSD，查询 SAP 核实表结构与函数签名，一轮写出符合框架和编码规范的开发方案与 232 行代码，静态校验零告警；批注修订、版本、差异、依据、导出在浏览器中可用。发现两个问题，已当场修复（DEV-E2E-01、02）；无 FSD 场景模型没有先出方案（DEV-E2E-06，待决定），单轮 token 用量偏高（DEV-E2E-04）；剩余场景见第 4 节。

## 2. 场景与结果

### 2.1 有 FSD 的报表（00021 采购订单执行清单（V1））

| 轮次 | 输入                                                                              | 结果                                                                                                                                                                                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | “请根据设计助手已写好的最新版 FSD，写开发方案和代码。程序名用 ZMM_PO_EXEC_LIST。” | 工具调用：`read_material`（FSD 第 2 版，定稿）→ `ddicElement`（EKET）→ `objectStructure` / `getObjectSource`（`ME_DISPLAY_PURCHASE_DOCUMENT` 签名）→ `write_artifact`（方案 4210 字符）→ `write_artifact`（代码 232 行，自动校验未发现问题）。第 1 版保存。最后一次模型调用时供应商断开连接（`socket hang up`），本轮标为失败，版本不受影响（DEV-E2E-01） |
| 2    | 代码批注：CTE 汇总了整张 EKET，没有过滤条件                                       | 模型改了开发方案两处，回复批注称“已重构 select 方法中的 CTE”，**代码没有任何改动**（第 2 版代码与第 1 版相同）。程序没有发现（DEV-E2E-02）                                                                                                                                                                                                                |
| 3    | 修复后重发：“批注还没有落实……请真正修改代码”                                      | `edit_artifact` 修改 select 方法，过滤条件进入 CTE，第 3 版代码 8491 字符，校验通过。39 秒                                                                                                                                                                                                                                                                |

生成代码与规范的符合情况（人工核对第 1 版）：程序头、`TABLES`、选择屏幕分块、影子范围表 `s_ekorg1`、`check_authority`（含 `EXCEPTIONS`）、继承 `YCL_FRH_REPORT`、`gt_out` 为 PUBLIC、CTE 汇总与 SQL 中 `CASE` 计算未清数量、逐列字段目录与 `coltext` 文本符号、默认排序、双击跳转且跳过合计行、无数据时 `LEAVE LIST-PROCESSING`、事件块只做调用，均符合。结构与范例高度一致（需求相同）。用量：第 1 轮输入约 19.2 万 token、输出 1.2 万 token，6 次模型调用。

### 2.2 无 FSD（00016 总账科目余额表）

输入：“财务想要一个总账科目余额表：按公司代码、会计年度、期间看每个科目的期初、借方、贷方、期末余额。”

- 结果：一轮完成，5 分 44 秒，第 1 版开发方案 3833 字符、代码 211 行。约 25 次 SAP 查询（ACDOCA 结构、记账期间、凭证状态域取值等），其中 4 次 SQL 写错后自行改正。选用 ACDOCA，在 CTE 中用 `CASE` 计算期初、借方、贷方、期末；公司代码按 `F_BKPF_BUK` 做 SRI 权限检查。
- 静态校验在写入后发现一处旧式 SQL，模型随后改正，最终校验通过——校验对模型起到了纠正作用。
- **未按要求先出方案并停下**（DEV-E2E-06）：没有 FSD 时系统指令要求先写开发方案、停下等审阅，模型却一轮写完方案和代码，没有提问；“不包含未过账的预制凭证”等业务口径由模型自行假设。
- 尝试回复一条不存在的批注，被程序拒绝。
- 用量：输入约 105 万 token、输出约 2.1 万 token（DEV-E2E-04）。

### 2.3 浏览器

- 设计阶段：会话、出题卡片、版本卡片、文档面板（版本切换、批注、导出）在前端改造后均正常。
- 开发阶段：开发清单“开发”按钮对报表、功能开放；工作台显示“开发”标签与开发助手；资料面板“成果”中代码页签（高亮、行号、复制）、开发方案、差异、依据、批注均可用。

## 3. 问题

| 编号       | 问题                                                                                                                                                                                  | 处理                                                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DEV-E2E-01 | 供应商在模型尚未输出时断开连接，整轮失败                                                                                                                                              | 已修复：`agent-core` 对尚未输出任何内容时的网络错误（`ECONNRESET` 等）按繁忙同样的节奏重试；已有输出时不重试，避免重复内容。两个助手都受益                                                                                                                                         |
| DEV-E2E-02 | 模型回复批注声称已改代码，实际没改                                                                                                                                                    | 已修复：批注针对的代码或开发方案本轮没有改动时，程序拒绝“已修改”的回复，要求先 `edit_artifact` 或以 `no_change` 说明理由；系统指令同步说明。修复后重跑，模型真正修改了代码                                                                                                         |
| DEV-E2E-03 | 模型在第 3 轮把第 2 轮没改代码归因于“网络中断”，与事实不符                                                                                                                            | 记录。模型自述不可信，以程序比对与版本差异为准；界面已显示每版差异                                                                                                                                                                                                                 |
| DEV-E2E-04 | 每次模型调用都携带系统指令、开发类型规范、范例、框架接口和会话事实（单次约 3 万 token）；查询多的轮次累计很高：2.1 第 1 轮约 19 万 token，2.2 一轮约 105 万 token（约 30 次模型调用） | 待优化：确认所用模型的提示词缓存是否生效；必要时把范例与框架接口改为按需读取，或限制单轮 SAP 查询次数                                                                                                                                                                              |
| DEV-E2E-05 | SAP 同步无法指定激活版或未激活版（内置 MCP 不支持传 `version`）                                                                                                                       | 记录于实施计划 5.7 节；首版不区分                                                                                                                                                                                                                                                  |
| DEV-E2E-06 | 没有 FSD 时，模型没有先写方案停下，而是一轮写完方案和代码，业务口径自行假设                                                                                                           | **待用户决定**。方向决策 2.3 定为“由模型决定、系统指令约定”，本次模型没有遵守。可选：① 加强系统指令措辞并在资料中显式标出“本开发项没有 FSD”；② 由程序在没有 FSD 且没有开发方案版本时，拒绝同一轮写入代码（相当于恢复一道程序门，与设计决策原则相反）。建议先做 ①，在更多样本上观察 |
