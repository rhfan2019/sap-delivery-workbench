# FSD 附录 D 测试案例与真实测试单据（2026-10-15）

## 1. 需求（用户 2026-10-15 确认）

- 设计助手 `abap-fsd-agent` 产出的 FSD 新增必备章节“附录 D 测试案例”：从 FSD 涉及的标准对象的生命周期、颗粒度、状态、取数逻辑推导测试案例。
- 用途：开发助手 `abap-dev-agent` 中开发人员据此做开发内测；后续测试助手 `abap-test-agent` 以它为种子注入并进一步扩充。
- 测试案例要配**真实单据号**（工作台的核心亮点）：先用 MCP 在系统中查找；找不到时弹框请用户授权，由助手在系统中建立所需单据。
- 确实不需要测试案例的程序，附录 D 写明“无需测试案例”及原因。
- 历史 FSD 不补写；可用现有 FSD 做实测，结果交用户复核。

## 2. 附录 D 格式（用户确认）

| 小节               | 内容                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| D.1 测试范围与策略 | 按四个维度覆盖了哪些场景、对应附录 B/C 的结论；测试系统与 client；不覆盖的内容                                   |
| D.2 测试数据       | 表：数据编号 \| 对象 \| 单据号 \| 数据特征 \| 核实条件 \| 来源 \| 核实时间。来源为“系统已有 / 本次新建 / 未找到” |
| D.3 测试案例       | 表：编号 \| 场景 \| 维度 \| 类型 \| 测试数据 \| 操作 \| 预期结果 \| 对应条款 \| 优先级                           |
| D.4 未覆盖与待补   | 找不到数据的场景及所需数据特征；留给测试阶段的扩充方向                                                           |

取值：维度为生命周期、颗粒度、状态、取数、权限、消息；类型为正向、排除、边界、异常；优先级为 P1/P2/P3。

## 3. 阶段 1（本次实施）：格式、方法、校验、只读查找单据

- 系统指令 `abap-fsd-agent/prompts/system.md`：第五部分第 11 条“测试案例与真实测试单据”（推导方法、分步单表查询找单据、核实条件）；第八部分文档结构加入附录 D 及深度要求；边界改为“测试案例只写附录 D”，并声明不能创建单据；自检表加一行。
- 文档校验 `tools/check.mjs`：附录 D 必备；D.1～D.4 齐全或写明“无需测试案例”及原因；两张表的列名与顺序；编号、维度、类型、优先级取值；测试数据编号与正文章节引用存在；预期结果不能是“符合预期”。
- 防编造：来源为“系统已有/本次新建”的单据号必须在本会话 SAP 结果中出现过（本轮完整结果、此前各轮的结果摘要，或上一版文档 D.2 中已核实的单据号），忽略前导零。SAP 不可用时不做此项。
- 测试：单元测试覆盖格式与取值规则、单据号匹配；集成测试覆盖循环以 SAP 结果为证据、跨轮沿用上一版单据号。

## 4. 阶段 2（待实施）：经授权在 QAS 建测试单据

用户已同意以下设计，单独实施、单独验证：

1. **白名单**：后台管理 →“SAP 系统”增加白名单维护，配置允许调用的 BAPI / 函数模块 / 类。
2. **目标系统**：测试单据建在 **QAS**；PRD 一律拒绝。
3. **个人凭据**：项目层面配置 DEV、QAS 的基本信息（URL、client 等）；用户名和密码必须是用户本人的，在网页的每个会话中由用户输入一次，或使用浏览器的保存机制。
4. **授权卡片**：查不到单据时，助手列出要建的单据、关键数据、BAPI、目标系统与 client，用户逐次同意后执行。
5. **执行方式**：在 `$TMP` 中生成固定前缀的临时类（`IF_OO_ADT_CLASSRUN`，调用白名单 BAPI 并提交），语法检查、激活、`runClass` 运行，返回单据号后写入 D.2，来源标“本次新建”。
6. **审计**：记录授权人、执行的代码、目标系统和建出的单据。
7. **契约**：先把契约 3.1 从“SAP 只读”改为“只读 + 经用户逐次授权的测试数据创建”，同步更新检查规则，agent-core 新增受控写入工具。
