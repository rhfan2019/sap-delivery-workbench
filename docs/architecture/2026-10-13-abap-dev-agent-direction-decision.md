# ABAP 开发助手方向决策

> 2026-10-13。状态：草案第 2 稿，待用户审阅。第 2 稿按用户对第 1 稿的答复重写：FSD 不作为前置条件，产物为单份程序，语法检查预留，增加从 SAP 同步代码。本文沿用 [FSD 设计助手方向决策](2026-10-11-fsd-assistant-direction-decision.md)（下称“设计决策”）的原则，只记录开发助手不同之处。本文本身不授权改代码；第 7 节的模块拆分须先按 AGENTS.md 修订[目录与依赖契约](repository-contract.md)及检查规则后执行。

## 1. 决策

开发助手 `abap-dev-agent` 与设计助手同构：一个可配置的模型，配一份系统指令（ABAP 开发规范）、一组 SAP 只读工具和代码编辑工具，在对话中自主决定提问、查证、写代码和修改。系统只保存对话、代码版本和批注，不设阶段状态机，也不检查 FSD 的状态。

使用者统称**开发顾问**。

## 2. 工作模式

### 2.1 资料，而不是前置条件

开发助手的输入是一组资料，每一项都可以缺：

| 资料         | 来源                                                         |
| ------------ | ------------------------------------------------------------ |
| FSD          | 设计助手的任一版本；业务顾问手工上传到开发项的文件；对话中上传的附件；或者没有 |
| 其他附件     | 需求文档、截图、样例数据、旧程序等                           |
| 开发顾问说明 | 对话中的补充与纠正                                           |
| SAP 事实     | 只读工具查到的表、字段、配置、FM/BAPI 签名、已有程序源码     |

不要求 FSD 已定稿，不绑定 FSD 版本；开发顾问可以早于业务顾问开始工作。**没有 FSD 时，开发顾问就是设计者**：助手要多问业务问题，并把它理解的业务规则写进开发说明（见 2.5）留痕。

### 2.2 循环，而不是流水线

```text
资料（FSD / 附件 / 说明） → 澄清 → 补充或纠正 → 生成代码 → 补充或纠正 → 生成代码 → …
        ↑                                                              │
        └──── 任意时刻：重新上传 FSD、在 SAP 中改了代码、加批注 ─────────┘
```

每一轮由助手判断这一轮该做什么，做完即停下等待：

- 资料不足或互相矛盾，且只有开发顾问能定 → **提问**
- 信息足够 → **写或改代码**，自动校验后停下
- 开发顾问只是在问问题 → **回答**

### 2.3 澄清什么

设计助手问的是业务规则；开发助手主要问实现层面的问题：用 BAPI 还是直接更新，加锁与提交策略；选择逻辑与数据量（是否分批）；出错时如何提示、是否记日志、是否回滚；命名规范、权限检查、与已有程序的关系；FSD 没写清或前后矛盾之处。没有 FSD 时，也问业务规则。

能在 SAP 中查到的不问，先查。

### 2.4 资料更新与冲突

资料随时可能变化，助手按以下规则处理：

1. **新 FSD**：先列出相对上一份资料的变化及其对代码的影响。与对话中开发顾问的**明确决定**冲突的，必须提问，不得默认以新 FSD 为准而覆盖；不冲突的直接改代码，并在回复中说明改了什么。
2. **开发顾问在 SAP 中改了代码**：开发顾问在对话中告知后，助手从 SAP 读取最新源码，作为新版本保存（来源标为“SAP 同步”），并与上一版本比对，弄清开发顾问改了什么；之后的修改都基于这一版本，不得把开发顾问的手工修改冲掉。
3. **优先级**：开发顾问在对话中的最新明确决定 > 最新资料 > 较早资料。助手依据的任何取舍都记入开发说明。

### 2.5 产物：一份程序 + 开发说明

- **程序**：每个开发项产出一份完整程序。报表是一个程序；接口与增强也写成一份代码，需要封装时用局部类（local class）。目的是让开发顾问能整份复制粘贴到 SAP。第一版不支持一个开发项多份程序。
- **开发说明**：代码里放不下、开发顾问需要知道或手工完成的内容：程序属性、文本元素、选择文本、消息类、需要新建的 DDIC 对象、事务码；关键假设；与 FSD 不一致之处及原因。
- **版本**：程序与开发说明一起构成一个不可变版本快照，可打“定稿”标签。来源分为“助手生成”“开发顾问编辑”“SAP 同步”。
- **批注与修订**：开发顾问对代码行或开发说明加批注，助手逐条局部修改并回复，开发顾问标记解决（同设计决策 5.2 节）。修改证据同样由模型声明、程序独立比对。

## 3. 范围

**第一版做：**上述工作模式；SAP 只读查询；从 SAP 读取已有程序源码（同步与参考）；程序端静态校验（见第 5 节）；代码查看、批注、版本差异、复制与导出。

**第一版不做：**

- **语法检查**：预留。ADT 语法检查需要 SAP 中已存在的对象作为上下文，方案由用户另行验证后再定。代码中不预埋开关，接入时按当时方案增加校验步骤。
- **写入 SAP**：创建或修改对象、激活、传输请求、对象锁、ATC、单元测试。后期开放写入须另写决策，重新设计权限、传输和回滚。

## 4. 工具

**SAP 只读工具**：沿用设计助手的 13 个只读工具及其 SELECT 限制、行数上限。

**代码工作区工具**（对应设计助手的 `tools/workspace.mjs`）：

| 工具             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| `list_materials` | 列出当前可用资料：设计助手的 FSD 版本、开发项上传的文件、对话附件 |
| `read_material`  | 读取某份资料，可按章节读                                     |
| `read_code`      | 读当前程序或开发说明，可按行范围读                           |
| `write_code`     | 整体写入程序（初稿或重写）；单次写不完时追加续写             |
| `edit_code`      | 唯一原文替换，用于局部修订，可关联批注编号                   |
| `write_notes`    | 写开发说明                                                   |
| `sync_from_sap`  | 按程序名从 SAP 读取完整源码，保存为“SAP 同步”版本，返回与上一版本的差异 |
| `check_code`     | 手动触发一次完整静态校验                                     |
| `ask_user`       | 与设计助手相同                                               |

`sync_from_sap` 由程序完整读取源码并入库，只把差异交给模型，不把整份源码塞进上下文。原因是巨石程序常有上千行，而设计助手为模型设的 `getObjectSource` 上限是 400 行，不能用它来同步。

## 5. 校验

每次写入后自动执行，结果作为提示交给模型，不退回、不中断（同设计决策）：

- 源码中引用的表和字段在 SAP 中存在（复用设计助手的核对逻辑）。
- 源码中的 `TEXT-xxx`、选择屏幕参数、消息号与开发说明中列出的一致。
- 程序完整：没有截断，`FORM`/`METHOD`/`CLASS` 等块配对。
- 语法检查接入后加入此处。

## 6. 数据

表前缀 `abap_dev_agent_`，归 abap-dev-agent 模块：会话、轮次、消息、工具调用、附件（与设计助手同构）；代码版本（程序 + 开发说明 + 来源 + 标签）；批注（关联行范围或开发说明）；会话登记的 SAP 程序名（用于同步）。

## 7. 模块与复用

智能体系统分三层：

| 层                 | 职责                                                         | 本项目                             |
| ------------------ | ------------------------------------------------------------ | ---------------------------------- |
| 模型接入           | 统一各家模型的流式输出、工具调用格式、计费                   | `models` 模块（已有）              |
| 智能体循环（Harness） | 调模型 → 执行工具 → 回填结果 → 直到停下；步数与工具调用上限、繁忙重试、空闲超时、取消、事件推送、重启时标记中断 | 现混在 `abap-fsd-agent/loop.mjs` 等处 |
| 具体智能体         | 系统指令、工具、产物存储、校验                               | `abap-fsd-agent`、`abap-dev-agent` |

**后端：**

1. 把中间一层抽成**公共运行模块**（名称待定，见第 10 节），不含 FSD 或代码相关内容，也不含表；通过参数接收工具、系统指令和持久化回调。附件解析一并迁入。暂不引入外部框架（如 pi-agent-core）：现有循环已跑通、模型兼容已由 `models` 处理，替换收益不明显，待两个助手稳定后再评估。
2. abap-fsd-agent 迁出后行为不变，测试全部通过。
3. abap-dev-agent：系统指令、工作区工具、校验、自有表与仓储。通过 `abap-fsd-agent/public.mjs` 读取设计助手的 FSD；通过 delivery 的 `context.mjs` 读取开发项上传的文件。

判断标准：两个助手都用、并且与产物无关的才放公共模块。不为假想的第三个助手设计扩展点。

**前端：**`ItemWorkspaceView` 改为工作台外壳（顶栏、对话时间线、输入框、附件、提问卡片、运行步骤），按阶段放入产物面板：设计阶段为现有文档面板；开发阶段为代码面板（单份程序查看与高亮、开发说明、版本与差异、批注、复制与导出）。代码高亮沿用现有 shiki（已支持 abap）。阶段之间的文字差异集中配置。

**审计日志**：audit 通过两个助手各自的 `public.mjs` 读取运行记录，不跨模块查表。

## 8. 验证顺序

1. **抽取公共运行模块**：abap-fsd-agent 全部测试通过，DEV-0031 回归一轮对话，单独提交。
2. **开发助手端到端**：以 DEV-0024 的 `02. FSD.md` 作为上传资料，跑完“澄清 → 生成 → 批注修订 → 重新上传修改过的 FSD → 冲突提问 → 修改”全流程；再在 SAP 中手工改一处、同步、继续修改，确认手工修改不被冲掉。
3. **无 FSD 场景**：只给一段口头需求，检查助手是否先问业务问题并把规则写进开发说明。
4. 评判：端到端完成、开发顾问评审业务逻辑、批注修订只改该改之处、冲突是否都提问、耗时；记录模型名称。语法正确性在语法检查接入前由开发顾问粘贴到 SAP 后检查。

## 9. 风险

| 风险                               | 应对                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| 无语法检查，代码错误到粘贴时才暴露 | 静态校验兜底；系统指令要求调用前查签名；语法检查方案确定后尽快接入 |
| 巨石程序长，单次输出截断           | 追加续写；完整性校验发现截断只续写缺失部分；修订优先 `edit_code` |
| 多份资料相互矛盾，助手悄悄取舍     | 2.4 节冲突规则写入系统指令；取舍记入开发说明，修改证据比对兜底 |
| SAP 同步读到未激活或错误的对象     | 同步前确认程序名；结果中注明读取的是激活版还是未激活版（实现时验证 ADT 行为） |
| 抽取公共模块影响已上线的设计助手   | 先抽取、回归通过并提交，再开始开发助手编码                   |

## 10. 待用户确认

1. 公共运行模块的名称。契约已禁用 `agent-runtime`，建议 `agent-core`。
2. SAP 同步读取激活版还是未激活版：开发顾问在 SAP 中改完未激活时，是否以未激活版为准。建议**以未激活版为准**（开发顾问刚改的就是它），读不到时退回激活版。
