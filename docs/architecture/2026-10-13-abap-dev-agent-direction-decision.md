# ABAP 开发助手方向决策

> 2026-10-13。状态：草案，待用户审阅。本文沿用 [FSD 设计助手方向决策](2026-10-11-fsd-assistant-direction-decision.md)（下称“设计决策”）的原则，只记录开发助手不同之处。本文本身不授权改代码；第 6 节的模块拆分须先按 AGENTS.md 修订[目录与依赖契约](repository-contract.md)及检查规则后执行。

## 1. 决策

开发助手 `abap-dev-agent` 与设计助手同构：一个可配置的模型，配一份系统指令（ABAP 开发规范）、一组 SAP 只读工具和代码编辑工具，在对话中自主决定提问、查证、写代码和修改。系统只保存对话、代码版本和批注，不设阶段状态机。

与设计助手的区别只在产物、工具和校验：

| 项       | 设计助手                     | 开发助手（第一版）                                     |
| -------- | ---------------------------- | ------------------------------------------------------ |
| 输入     | 需求、附件                   | 开发项的**已定稿 FSD 版本**、附件                      |
| 产物     | 一份 Markdown FSD            | 一组 ABAP 源码对象 + 一份实施清单                      |
| SAP      | 只读                         | 只读，另加**语法检查**（不保存、不激活）               |
| 自动校验 | 章节、表格、表与字段存在     | 语法检查、表与字段存在、对象清单与实施清单一致         |
| 批注     | 对文档文字                   | 对某个对象的某几行代码                                 |
| 权限     | `fsd` 阶段负责人             | `development` 阶段负责人                               |

## 2. 范围

**第一版做：**

- 生成代码文本，顾问在平台内查看、批注、修改，然后导出，自己在 SAP 中创建对象并粘贴。
- 对象类型先限定为**单个可执行报表**：一个主程序；局部类、选择屏幕、ALV 写在主程序内。不拆分 INCLUDE（待确认，见第 9 节）。
- **实施清单**：顾问需要手工完成、源码里放不下的事项。例如程序属性、文本元素、选择文本、消息类、需要新建的 DDIC 对象、权限对象、事务码。由模型编写，程序校验它与源码中的引用是否一致（例如源码用了 `TEXT-001`，清单里就必须有这个文本元素）。
- 每次写入后自动做语法检查，结果作为提示交给模型，不退回、不中断（同设计决策 5.2 节“校验”）。

**第一版不做（后期条件成熟再做）：** 在 SAP 中创建或修改对象、激活、传输请求、对象锁、ATC、单元测试；函数组、类、DDIC 对象的源码生成；增强与 BAdI 实现。后期开放写入时，须另写决策，重新设计权限、传输和回滚，不在本版预埋开关。

## 3. 一轮对话

与设计决策 5.1 节相同，只是目标换成“输出能通过语法检查、能落实 FSD 的代码”：

```text
用户消息（开始开发 / 补充信息 / 修改意见 / 批注）
  → Agent 判断：离写出或改好代码还缺什么
  → 对照 FSD 推导需要核实的 SAP 对象（表、字段、FM/BAPI 签名、已有程序），批量查询
  → 缺的是只有客户或设计能定的事 → 向用户提问，停下
     信息足够                     → 写或改代码，自动语法检查后停下
     用户只是提问                 → 回答，停下
```

FSD 有错误或缺漏时，开发助手**不修改 FSD**：在回复和实施清单中列为“与 FSD 的偏差”，由顾问回到设计助手处理。

## 4. 工具

**SAP 只读工具**：沿用设计助手的 13 个只读工具，以及相同的 SELECT 限制、行数和源码行数上限。

**语法检查**：只开放 abap-adt 的 `syntaxCheckCode` 一个工具，由程序在每次写入后自动调用；是否同时让模型主动调用，按验证结果再定。

> **技术风险（第 7 节验证 1）**：ADT 语法检查必须指定一个 SAP 中**已存在**的对象 URL 作为上下文，再传入待查源码，不保存。新报表在 SAP 中还不存在，拟由每个 SAP 连接登记一个**语法检查占位程序**（例如 `ZSDW_SYNTAX_CHECK`，由顾问在 SAP 中建一次空程序），用它的 URL 检查新代码。此方案须先在实际系统上验证。

**代码工作区工具**（对应设计助手的 `tools/workspace.mjs`）：

| 工具              | 作用                                                         |
| ----------------- | ------------------------------------------------------------ |
| `read_code`       | 读对象源码或实施清单，可按行范围读                           |
| `write_code`      | 整体写入某对象（初稿或重写）；单次写不完时追加续写           |
| `edit_code`       | 唯一原文替换，用于局部修订，可关联批注编号                   |
| `write_checklist` | 写实施清单                                                   |
| `check_code`      | 手动触发一次完整校验（语法、表与字段、清单一致性）           |
| `ask_user`        | 与设计助手相同                                               |
| `read_fsd`        | 按章节读取作为输入的已定稿 FSD                               |

修改证据与设计助手相同：模型声明修改清单，程序独立计算差异比对。

## 5. 数据

表前缀 `abap_dev_agent_`，归 abap-dev-agent 模块：会话、轮次、消息、工具调用、附件（与设计助手同构），以及：

- **代码版本**：不可变快照，一个版本包含全部对象源码和实施清单；支持“定稿”标签。
- **批注**：关联对象名与行范围，未解决 / 已解决由用户控制。
- **会话的 FSD 来源**：记录开始开发时引用的 FSD 会话与版本号。FSD 之后又出新定稿时，界面提示“FSD 已更新”，由用户决定是否让助手按新版修改，不自动切换。

## 6. 模块与复用

**后端拆三块：**

1. **公共智能体运行模块**（新增，名称待定，见第 9 节）：模型调用循环（步数与工具调用上限、模型繁忙重试、空闲超时、取消）、轮次事件流、服务重启时标记中断、附件解析。不含任何 FSD 或代码相关的内容，也不含表；通过参数接收工具、系统指令和持久化回调。
2. **abap-fsd-agent**：迁出上述通用部分后行为不变，测试全部通过。
3. **abap-dev-agent**：系统指令、代码工作区工具、语法检查、自有表与仓储；通过 `abap-fsd-agent/public.mjs` 读取已定稿 FSD。

判断标准：两个助手都用、并且与产物无关的才放公共模块。宁可先少抽一些，不为假想的第三个助手设计扩展点。

**前端：**`ItemWorkspaceView` 改为工作台外壳（顶栏、对话时间线、输入框、附件、提问卡片、运行步骤），按阶段放入产物面板：设计阶段为现有文档面板，开发阶段为新的代码面板（对象列表、代码查看、版本差异、语法检查结果、批注、实施清单、导出）。代码高亮沿用现有 shiki（已支持 abap）。文字差异按阶段配置，不在组件里散落条件判断。

**审计日志**：audit 需同时读取两个助手的运行记录，各自通过 `public.mjs` 提供，不跨模块查表。

## 7. 验证顺序

1. **语法检查可行性**（编码前，半天以内）：用实际 SAP 连接，确认在占位程序上传入未保存的新报表源码能返回正确的语法错误和行号，且不改动占位程序。如果不可行，改为只做程序端静态检查，并重新评估第 2 节的范围。
2. **抽取公共运行模块**：abap-fsd-agent 全部测试通过，DEV-0031 回归一轮对话。
3. **验收**：用 DEV-0024 的定稿 FSD 生成报表。评判：端到端完成、语法检查通过、实施清单完整、顾问评审业务逻辑与 FSD 一致、按批注修订只改该改之处、耗时。记录模型名称。

## 8. 风险

| 风险                               | 应对                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| 语法检查依赖占位程序，各客户需配置 | SAP 连接登记中增加该字段，未配置时跳过语法检查并在界面提示   |
| 报表源码长，单次输出截断           | 追加续写；语法检查发现截断时只续写缺失部分                   |
| 模型虚构 FM/BAPI 参数              | 系统指令要求调用前查签名；自动校验核对表与字段               |
| 抽取公共模块影响已上线的设计助手   | 先抽取、回归通过并提交，再开始开发助手编码                   |

## 9. 待用户确认

1. 公共运行模块的名称。契约已禁用 `agent-runtime`，建议用 `agent-core`。
2. 开发能否基于未定稿的 FSD 开始？建议**必须有定稿版本**，否则开发助手入口提示先定稿。
3. 第一版报表是否允许拆分 INCLUDE（TOP / SEL / F01 等）？建议**不拆分**，一个主程序即可，降低语法检查和导出的复杂度。
4. 语法检查占位程序的命名，以及由谁在客户系统中创建。
