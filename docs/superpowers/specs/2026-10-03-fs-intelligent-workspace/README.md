# FS 智能工作区设计交付索引

推荐以主 Agent、显式工作流、结构化文档和服务端审批门禁实现完整交付闭环。范围为传统 S/4HANA OP/PCE ABAP；本包不修改产品代码，也不宣称已完成 SAP 技术验证。

- [主设计方案](design.md)：按要求的12部分组织，含参考资产评估、架构、领域、界面线框、状态/时序、容错、清账演示、MVP和来源。
- [完整提示词包](prompts/agent-prompts.md)：A—H共8份，主系统配置与7份阶段配置。
- [契约说明](contracts.md)：三层职责、六个要求的主Schema及额外契约、供应商子集、五级校验、合法/非法样例链接。
- [验收与评估](acceptance.md)：40项Given/When/Then产品验收条件和需求追溯矩阵；这些产品测试尚未执行。
- [Schema目录](schemas)：13份通用完整JSON Schema、7份OpenAI结构适配。
- [样例目录](examples)：13个合法、13个结构非法、6个结构合法但领域应拒绝的样例。
- [设计包校验报告](validation-report.json)：91项检查通过，非真实平台/SAP/模型API联调。
- [来源文件指纹](source-manifest.json)：本次研究的本地文件路径与SHA-256；不包含凭证或SAP业务数据。

阅读顺序：先主方案1—5章评估产品与架构，再提示词及契约，最后验收与分期。JSON及提示词文件是主方案第6/7部分的完整配套，不是待补充占位。

尚未验证：目标SAP接口与运行时权限、模型供应商真实API接受性、平台动态行为、Word/PDF实际渲染与性能指标。文档中已分别标明验证责任和放行条件。

1. [可点击前端原型](prototype/index.html)与[前端详细设计](frontend-design.md)：管理、对话/文档、变更冲突、版本及评审发布页面，含响应式与交互规格。原型直接打开 HTML 即可使用；全部数据为演示。
2. [开发详细设计](engineering-design.md)与[OpenAPI 3.1 契约](api.openapi.json)：工程目录、模块职责、数据表、鉴权、并发、任务恢复、迁移和集成边界。
3. [AI 可执行实施计划](../../plans/2026-10-03-fs-intelligent-workspace.md)：T01—T15，列明文件、接口、测试和完成条件，尚未执行。
4. [AI 开发启动提示词](development-start-prompt.md)：可整段复制，明确要求检查并维护项目目录结构合理性。

建议先看原型，再读前端与工程详细设计，最后把启动提示词交给开发 AI。实现细节按补充工程设计落实（例如首版附件上限 5MiB）；原始方案中的长期目标不代表已实现能力。

[原型交互校验](prototype/qa-report.json)只覆盖独立演示；[API 静态校验](api-validation-report.json)只覆盖契约结构与引用，不代表接口已实现。真实 SAP、模型、扫描/OCR、导出与性能仍须在实施过程中验证。
