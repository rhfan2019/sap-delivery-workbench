- 任务：用 GitHub skill 阅读 open-webui/open-webui 与 openclaw/openclaw，总结其 Agent 工作台体验，对标本项目的不足，出具供 Codex 执行重构的专业报告。
- 产出：`artifacts/agent-workbench-benchmark-2026-10-04.md`
- 关键发现：
  - openclaw `packages/workboard-contract` 是可直接借鉴的看板领域契约（状态机/事件/诊断/claim）。
  - open-webui 的价值在实时协作基础设施（Socket.IO room + Redis），不在"聊天形态"。
  - 本项目运行内核（lease+fencing、快照哈希、事件单调序列、阶段状态机）已达对标水平，**缺的是工作台体验层**：无看板、无诊断、实时仅单 run 单端、无接管、无健康度。
- 给出 4 个优先项：P0 运行看板、P0 诊断引擎、P1 会话级实时通道、P1 运行接管。

## 前端交互体验对标（补充篇）

- 用户指出：上一轮报告偏后端，前端只做了目录级检索，未逐行评估交互。
- 补充产出：`artifacts/frontend-ux-benchmark-2026-10-04.md`
- **结论修订（重要）**：本项目前端「交互能力」不弱，反而是三者中单点交互质量最高的——
  已实测存在：中文输入法 composition 保护、滚动跟随+未读提示、rAF 节流渲染、
  SSE 游标严格连续性校验、幂等 client_message_id、13 个错误码→中文人话映射、
  拖拽分隔条+键盘可调。这些是 open-webui / openclaw 都没有或做得很粗的。
- 真正的根因缺陷：**F1 无全局状态层**（`apps/web/src/stores/` 仅 .gitkeep，
  未引入 Pinia），导致 run 生命周期 = 页面生命周期（`useFsWorkspace` 的 onScopeDispose），
  进而派生出无通知/无看板/无历史/无深链。F1 是根因，其余 11 项皆派生。
- 前端重构第一刀应建立全局运行状态层（Pinia，runs store），
  只改 runStream 的「持有者」不改「协议」；并注意保留 `generation` 竞态防护。
- 设计令牌缺口实测：`delivery.css` 硬编码 64 个颜色、`assistant-test.css` 36 个、`models.css` 31 个。
